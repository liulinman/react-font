# 交付记录模板

在已有功能目录使用此结构，按实际任务删去不适用字段。不复制 PRD 正文或测试报告，不提交秘密与原始运行日志。对本机临时报告用相对索引，交付给用户时给出真实绝对路径或可访问链接。

```markdown
# <功能>交付

## 本轮范围与授权
- 日期、工作区、用户要求：
- 模块、功能、端/角色：
- 起止阶段：
- commit / push / 部署授权及来源：
- 远程/分支、环境、服务范围：
- 非本任务改动与保护方式：

## 基线与追溯
- 前端起始分支/SHA/dirty：
- 后端起始分支/SHA/dirty：
- 正式 PRD、决定补充、摘要：
- 确认UI设计/原型、版本/摘要与确认依据；不适用原因：
- Spec Kit版本/实际执行记录、Spec/plan/tasks及摘要：
- PRD → 设计状态 → Spec场景 → 实现 → Case 映射：
- 本轮审查问题与处理：

## 产物导航
- 结构化本轮记录delivery.json及全局docs/delivery/index.json条目：
- featureId / changeId；本轮delivery与持久索引：
- 正式PRD/决定；Spec/plan/tasks/质量清单：
- UI说明、可点击原型及运行方法、批准版本与原型截图：
- Case/suite/test映射与追踪文件：
- 各次run ID、运行目录/清单、实现截图、报告和AI分析：
- 各次真实Cloud run URL、完整归档位置与保留期限：
- pending/blocked/skipped产物及原因（不能用空文件填充）：

## 阶段状态
| 阶段 | 状态 | 证据 | 未完成原因/下一步 |
|---|---|---|---|
| PRD | pending | | |
| 需求审核 | pending | | |
| UI/交互设计与确认 | pending | | |
| Spec/一致性核对/计划任务 | pending | | |
| 研发/代码审查 | pending | | |
| 公开文档同步 | pending | | |
| 自动化执行 | pending | | |
| 视觉/交互与人工验收 | pending | | |
| AI失败分析 | pending | | |
| Cloud | pending | | |
| 完整证据归档 | pending | | |
| commit/push/CI | pending | | |
| 部署 | pending | | |
| 线上验证 | pending | | |

## 本轮验收
- 受测前后端 SHA；若 dirty，记录实际补丁/输入摘要：
- 运行 ID 与环境：
- Case 总数、真实执行、通过/失败/跳过/未覆盖：
- 来源完整性、PRD/Spec各子条款覆盖缺口：
- 确认设计与真实浏览器的对照、视口/操作证据：
- 视觉/交互问题、整改复验、客户试用是否实际执行：
- 报告、AI分析、真实Cloud run URL：
- 运行清单、完整证据包/远端地址、上传验证、保留期限：
- 失败分类、修复与重跑关系：
- seed 数据与清理状态：
- 真实 AI 服务是否验证、替身证明边界：

## 提交与发布
- 两仓库最终 SHA 与关系：
- push 目标及远程确认、对应 CI：
- 是否自动触发部署：
- 发布环境、实际部署版本、产物摘要：
- 回滚点、配置备份索引与恢复状态：
- 线上实际验证、时间与限制：
- 剩余风险/阻断、下一步：
```

阶段状态不替代 Case 级原始结果。多次执行保留各自运行 ID，修复重跑不得覆盖第一次失败。源码、PRD 或部署产物改变后，核对哪些旧证据失效；不因为文件名相同就沿用“已通过”。
