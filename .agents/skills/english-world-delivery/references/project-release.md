# 项目执行与发布定位

本文件是定位线索。执行时重新读取当前仓库文件，不把此处描述作为永远有效的命令或授权。所有命令从对应仓库执行，运行前核对 package.json 与工具版本；不要为本机版本问题擅改项目锁定版本。

## 先用已有测试流程

从 `react-font/`：

```sh
pnpm test:prd --list
pnpm test:prd --module <本轮模块> --plan
```

默认Cloud；用户明确仅本地时，手动固定重放省略 `--cloud`，后台AI入口按当前文档使用 `--local-only`。不要把“本地研发、不部署”自行解释成不记录Cloud。

按当前项目 skill 选择两条路线之一，不将两条路线混为一谈：

- **后台 AI 生成与分析**：`pnpm test:prd:ai --module <模块>` 或 `--all`。默认 Cloud；明确仅本地才使用 `--local-only`。真实生成和分析在隔离任务内进行，需要当前配置要求的 AI provider、凭据与运行环境。检查 `test-results/ai/<id>/` 的本次任务状态及报告。失败时保留现场，不能假装后台仍在工作。
- **当前 Codex 手动维护并执行**：读取完整 PRD，修订 Case/脚本/binding 后执行 `pnpm test:prd --module <模块> --cloud` 或 `--all --cloud`。这是重放固定脚本，由当前会话负责需求分析和失败分析，不能声称启动后台 AI。缺后台凭据时可在当前授权允许且能完成工作时明确采用此路线；Cloud 要求仍保留。

Case 在 `docs/testing/cases/`，suite 在 `docs/testing/suites.json`。测试环境、seed、端口和清理要求见 `docs/testing/prd-testing.md`；不占用或停止不相关服务，不连接生产数据库跑隔离 seed。

手动路线本次证据在 `test-results/prd/<run-id>/`。根据当前输出编写 `analysis.json/md`，再用 `pnpm test:prd --finalize test-results/prd/<run-id>` 更新报告。正常退出、覆盖不足和执行/环境失败按当前执行器定义区分；禁止仅看最终控制台摘要。

Cloud 凭据从进程环境或项目允许的本地忽略文件读取，不在命令参数、聊天、Case、Git、报告暴露。run URL 必须取自此次实际返回。只提供 Cloud 项目主页不等于上传成功。检查报告和回放使用隔离账号、合成数据，不能上传真实用户私密数据。

## 文档同步

执行项目 `.agents/skills/english-world-docs-maintenance/SKILL.md`。至少按其要求运行 `pnpm docs:check` 与 `pnpm docs:build`，并验证受影响页面。前端、管理端、后端的构建与测试命令从各自 package.json 取，不以文档构建替代产品验收。

若本轮涉及 PRD 查看器或生成快照，仅在对应同步脚本确实存在时运行；核对唯一来源、内容摘要、鉴权和打包位置。不提前假定未完成的查看器或同步能力已存在。

## push 前识别自动部署

只读查看两个仓库 `.github/workflows/deploy.yml` 的：

- push 分支与 `workflow_dispatch`；
- verify/deploy 依赖、并发策略及当前执行状态；
- 目标服务、产物来源与失败恢复；
- 数据库相关动作和前后端发布兼容要求。

两个仓库可能采用不同触发分支。当前工作分支、上游分支和触发分支也可能不同。不能为了触发自动部署自行更换目标分支、合并或覆盖远程。

如 push 已触发获准部署，就跟踪该次流水线，不再并行手动部署。同一环境已有运行中的发布时避免竞争；不要盲目取消他人的流水线。CI 或网络结果未知时读取实际状态再决定恢复。

## 发布范围与回滚点

前端静态变更通常只更换 frontend，携带本轮要求的学生端、管理端和公开文档产物；不重启无关后端或数据库。生产 Nginx 用已有增量合并方式保留 TLS/ACME，执行前重新核对当前实现。

后端变更必须核对独立后端工作流及当前线上模块、表结构与接口兼容；不能用本地完整镜像直接覆盖未经核实的线上能力。涉及迁移时检查迁移的实际授权、备份和应用版本兼容，遇到破坏性操作单独处理。

发布记录保留：环境标识、前后端 SHA、产物/镜像摘要、当前配置备份位置、迁移说明、应用回滚命令来源、回滚后检查。秘密留在既有安全存储，报告仅记录脱敏的资源位置与摘要。

上线验证按本轮变更选择：登录保护和匿名响应、关键业务读写、深链刷新与404、公开文档与资源、本轮涉及的电脑端学生端/管理端（移动端仅在用户明确重新纳入时验证）、PWA 实际加载版本。验证产生的业务数据需要明确允许与清理路径；无权限时记录验证限制，不能编造通过。
