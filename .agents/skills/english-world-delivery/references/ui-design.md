# UI/交互设计：客户任务、原型与验收

仅有UI影响时读取。路径相对实际 `react-font/`；先查已有设计目录和固定skill版本。设计不是在PRD之后临时装饰页面，而是将产品任务转换为可理解、可完成、可恢复的操作。

## 先定义真实任务

记录目标角色、使用场景、起点、主要操作、成功/失败结果及本轮端。学生学习页、管理后台和文档阅读分别服务学习、操作和理解，不能套同一种营销布局。

检查现有主题token、组件、典型页面和品牌资产，区分明确保留项与可调整范围。用真实长度的合成中文/英文、列表和边界数据设计；不根据空白占位图宣布信息层级合理。

“客户友好”落为可观察要求：

- 页面层级与用户任务一致，主要动作可辨，名称表达实际结果。
- 表单标签、必填/校验、提交中与防重清楚；错误保留必要输入，给恢复动作。
- 加载、空数据、失败、无权限、重试与危险操作确认都有适用设计。
- 导航/返回不丢上下文；键盘操作、焦点、可访问名称、对比和点击目标符合适用规范。
- 用户要求的视口、语言及主题不遮挡关键内容；长文本/列表不是只在理想样例里工作。

“去AI模板感”通过具体取舍检查：是否用无意义卡片拆散同一任务、装饰性数字/渐变抢占内容、每页同一模板、泛化文案暴露内部实现、无关动画妨碍操作。它们是需结合情境判断的线索，不是禁止所有卡片、圆角、渐变或动画。保留用户已确认的品牌，操作效率优先于新奇。

## 原型及可追溯交付

默认 `docs/design/<module>/<feature>/`；已有规范则复用。按任务需要形成：

- `design.md`：角色任务、流程、信息结构、页面/组件状态、文案、复用token/组件与确认记录，关联PRD条款。
- `prototype/` 或获准设计工具的版本链接：能够走通关键交互的原型，必要时有截图，不把截图当作可点击原型。
- 关键页面/状态截图和适用视口说明；本轮不涉及的端明确排除。

大改版可在隔离原型比较少量真正不同的方向；小改动直接展示聚焦差异，不机械生成多套。产物不能修改生产路由、业务代码、账号或数据；需要开发辅助代码时明确其原型用途与位置。

展示可审阅成果后请求用户确认重要设计方向和关键交互。已存在批准稿、用户已确认或明确委托的常规细节不重复确认。用户尚未确认的新视觉方向不得直接替换生产页面。确认记录标明artifact路径/版本/摘要、批准内容和仍未决点，不把“先看一下”当成批准。

用户要求跳过原型时记录其指令，仍遵守明确产品范围与基本交互要求，不声称设计已经用户确认。新业务规则回到PRD，新交互决定同步设计与Spec；不能让三份文档描述不同结果。

## 实现后的视觉与交互验收

在真实浏览器按角色完成任务，不只检查按钮存在。依据确认稿核对层级、组件、文案与状态；检查键盘/焦点、提交/等待/失败/返回/刷新等本轮适用行为。

使用本轮明确的端/视口；未指定时以代表性桌面视口验证，仅用户明确重新纳入移动端时才加移动检查，记录尺寸。不自动把桌面需求扩成手机研发。已有skill的截图/迭代上限照其实际规则执行，避免无边界审美打磨；阻断缺陷仍须明确修复与复验。

设计验收记录放在交付目录 `ui-review.md`：确认稿版本、受测代码版本、任务/视口、真实截图、操作与观察、问题严重度/用户影响、整改及复验、剩余人工项。声明代码检查、浏览器事实、推断和待验的区别。Cypress可验证状态与操作，视觉回归可辅助，但不能把有截图/像素相等当成“客户友好已证实”。没做客户试用就不能声称客户验证通过。
