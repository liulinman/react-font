# Cypress Cloud 与完整证据归档

执行/验收时读取，并以当前项目测试skill、文档与配置为实际入口。默认Cloud，用户明确仅本地则保留本地证据并说明未上传。

## 三层证据

1. **Cypress Cloud**：浏览器测试运行、结果及当前配置/订阅支持的截图/视频/回放。复用项目登记的私有项目，真实run URL来自本次工具返回。记录项是否实际存在应分别核实，不保证每次都有全部媒体或永久保留。
2. **完整运行目录**：现有 `test-results/prd/<run-id>/` 或后台 `test-results/ai/<id>/`，包含来源冻结、Case、前后端版本/dirty、执行结果、日志截图、`analysis.json/md`、HTML报告、UI审查与链接。Jest/Vitest、PRD/Spec/设计覆盖与我们的AI结论不自动进入Cypress Cloud。
3. **交付索引与远端归档**：`docs/delivery/<日期>-<feature>/delivery.md` 记录真实Cloud URL和证据包地址。被Git忽略的本地目录不能当长期存储；CI artifact核实上传与实际保留期限，需要长期保存时在授权范围接私有对象存储并核实访问权限/生命周期。没接入就写待办，不能称已备份。

默认基本归档是可回读的本地完整运行包、交付索引和已核实的Cloud记录（明确仅本地时省略Cloud）。仅用户要求远端完整备份或长期保存时，才把相应存储作为本次完成条件；未接通长期存储不阻止已授权基本范围完成，但必须明确本地包没有自动远端长期备份，不承诺永久留存。

## 统一运行清单

每次实际执行必须在运行目录维护 `run-manifest.json` 或复用执行器已有的等价清单；缺失时由编排补充并核对，不冒称执行器已自动生成。至少关联：feature ID、runId/重跑关系、PRD/决定/Spec/设计的实际路径与摘要、两仓库SHA/dirty及受测补丁摘要、测试环境、Case映射、执行/覆盖结果、UI与人工待验、AI分析状态、Cloud URL、归档地址与验证状态。

这是编排所需的记录，不代表执行器已经自动产出。schema不支持的内容放侧车，明确手工复核。无实际URL用未完成状态，不能填写虚构地址或拿项目主页冒充本次run。

## 实际执行与失败

从前端仓库按项目skill使用固定重放 `pnpm test:prd --module <模块> --cloud`，或已配置的后台AI `pnpm test:prd:ai --module <模块>`。用户明确仅本地时，固定重放省略 `--cloud`；后台路线使用当前项目文档实际支持的 `--local-only`，执行前核对入口。两者职责不同，前者由当前Codex维护和分析，后者必须等待真实生成、执行和分析阶段；控制台启动不等于任务完成。

Cloud上传失败保留本地结果与错误并单独标失败；不为完成结论省略--cloud。分析失败保留已执行报告并标待分析。修复后创建新run，与首次失败关联。真正复用结果须确认来源和受测内容一致，不能用旧版本的绿灯支持新改动。

CI失败或中断也尽量保存已有证据；核实workflow确实执行了artifact上传。当前保留期限、自托管runner、Secrets与工作流远程可用性必须从当前配置与运行确认，不能因为本地有YAML就承诺关机后继续跑。

## 隐私与验收结论

只用隔离合成账号/数据；上传前排除真实用户材料、密钥、Cookie和生产日志。不要为截图/回放泄漏权限测试中的秘密。Cloud Record Key、AI provider凭据只放允许的本地忽略文件、进程环境或CI Secrets，不写入manifest、命令参数、报告与Git。

只有本次范围PRD/Spec各子条款具备合格证据、关键设计/交互通过、必须人工/供应商项已验、AI分析完成、Cloud成功（或明确仅本地）以及本次要求的完整证据归档可用，才能称对应范围验收完成。分别展示执行通过率、需求覆盖、规格覆盖、UI结论与未完成项；Cloud全绿不代表上述条件全部成立。
