# English World 组件与状态

## 组件选择原则

先复用 Ant Design、Ant Design Mobile 和项目已有组件。只有当现有组件无法表达稳定的业务模式时才新增抽象；不要为单页视觉差异复制一套组件。

## 按钮与操作层级

- 每个页面或明确任务区只突出一个主要操作，使用 Primary Button。
- 次要命令使用 Default、Text 或菜单项；危险命令使用 Danger 语义。
- 工具栏中的撤销、刷新、下载、删除等熟悉操作优先使用图标；仅图标按钮必须有 `aria-label`，不熟悉的图标增加 Tooltip。
- 按钮尺寸固定，加载状态保留原宽度，避免文案变化推动相邻控件。
- 不把模式选择、二元设置或导航伪装成一排普通按钮：模式用 Segmented，二元设置用 Switch/Checkbox，视图用 Tabs，选项集用 Select/Menu。
- 主要操作不可用时解释原因；不要只有灰色禁用态。

## 表单

- 标签与输入建立程序化关联，必填、帮助、错误和格式要求紧邻字段。
- 校验在用户完成输入或提交时发生，不在每个按键后制造噪音。
- 提交中禁用重复提交并保留输入；失败后保留全部参数和用户内容。
- 移动端输入、Textarea 和 Select 的可编辑文字至少 `16px`，避免 iOS 聚焦缩放。
- 数值使用 InputNumber、Slider 或 Stepper；日期时间使用现有日期时间控件。
- 自定义公告、文章或题目等长文本在离开前提供未保存保护。

## 列表与表格

- 数据密集型页面优先使用列表或表格，不把每一行做成大型卡片。
- 表头、排序、筛选和分页保持位置稳定；重要状态紧邻对象名称。
- 行操作使用有限的高频动作和 More 菜单，危险操作与常规操作分离。
- 长标题单行截断时提供 Tooltip、`title` 或详情入口；不能截断唯一可识别信息。
- 空列表区分“没有数据”和“筛选后无结果”，分别提供创建/生成或清除筛选动作。
- 异步更新一行时只更新该行状态，不让整个列表闪烁或滚动位置跳变。

## Tabs、分段控件与筛选

- Tabs 用于同一对象或页面内的稳定视图切换。
- Segmented 用于少量互斥模式，通常 2-5 项。
- Select/Menu 用于较长或可扩展的选项集。
- 筛选条件应可见、可清除、可恢复；刷新和前进后退后保留关键状态时优先同步 URL。
- 移动端不强行压缩桌面 Tabs；可滚动、换成分段控件或放入筛选弹层，但能力不能静默丢失。

## 卡片与页面区块

- 卡片只用于重复条目、弹窗内容、独立练习工具或必须有边界的对象。
- 页面章节使用留白、分隔线和标题组织，不把章节包装成漂浮卡片。
- 禁止卡片嵌套卡片。确需内部结构时使用无框分组、列表或带分隔线的区域。
- 卡片标题使用紧凑字号，不在工具面板内部使用 Hero 级文字。

## 弹窗、抽屉与危险操作

- 简短确认使用 Modal；需要浏览、编辑或多步配置时使用 Drawer 或完整页面。
- 打开后焦点进入弹层，关闭后恢复到触发控件；键盘可完成全部操作。
- 危险操作明确写出对象、范围、后果和是否可恢复。
- 封禁、解封、删除、撤回等后台操作执行前必须二次确认；永久删除用户时第二次确认要求输入用户名或指定确认文本。
- 删除用户必须展示将被删除的数据范围，并由后端事务或可审计任务保证完整性；前端确认不能替代后端权限、幂等和审计。
- 未保存内容在关闭、刷新或离开时提示；取消操作不应意外提交。

## 通知、公告与 Toast

- 通知铃铛展示未读数量，打开后显示持久通知列表；已读状态以服务端为准。
- Toast 用于即时、短暂反馈，不替代需要稍后查看的通知记录。
- 同一公告在 Toast 和通知列表中共享标题、类型、发布时间和目标链接；Toast 消失后用户仍可从通知列表找回。
- 公告发布、定时发送、撤回和失败需要明确状态。撤回后服务端状态成为事实来源，客户端实时移除或标记失效。
- 不对同一事件重复弹 Toast；重连后去重并同步未读计数。
- 重要失败、账户封禁或练习中断不能只靠短暂 Toast，应提供页面内持久反馈。

## 通用状态

| 状态 | UI 要求 |
|---|---|
| Loading | 保留布局尺寸；列表用 Skeleton，短操作用 Spinner；说明正在处理的对象 |
| Empty | 解释为何为空，并给一个最合适的下一步 |
| Error | 显示可理解原因、受影响对象、是否保留数据及恢复动作 |
| Success | 确认结果并提供继续任务的入口，不制造多余庆祝动画 |
| Disabled | 保持可读，并说明何时可用或缺少什么条件 |
| Destructive | 使用危险语义、对象名称、影响范围和二次确认 |
| Undoable | 明确撤销时限和结果；撤销失败转为持久错误 |

颜色不是唯一状态信号。状态至少还应有文字、图标、标签或结构差异。

## AI 与长任务状态机

AI 生成、解析、批量导入和定时内容任务使用一致状态：

| 状态 | 用户看到什么 | 允许操作 |
|---|---|---|
| `idle` | 可编辑参数和生成入口 | 编辑、提交 |
| `validating` | 正在校验输入/题型 | 取消或等待 |
| `submitting` | 请求已发出，防止重复提交 | 等待 |
| `pending` | 已进入队列，显示创建时间 | 离开页面、查看详情、可选取消 |
| `processing` | 正在生成，显示阶段和最近更新时间 | 离开页面、刷新状态、可选取消 |
| `succeeded` | 结果摘要和主要下一步 | 开始练习、查看、下载或编辑 |
| `failed` | 可理解原因、失败阶段和原参数 | 使用原参数重试、修改后重试、删除记录 |
| `stale` | 长时间无进展，说明服务可能中断 | 刷新、重连、保留任务 |
| `reconnecting` | 正在恢复实时连接，不把任务标成失败 | 等待、手动刷新 |

必须满足：

- 服务端生成出可用练习后即可进入 `succeeded`，不得由额外的前端“质量门禁”把已生成结果改成失败。
- 若服务端返回部分可用结果，明确标记缺失项并允许用户决定继续或重新生成。
- `failed` 必须展示后端可公开的原因，不只写“生成失败”或“无法解析”。
- 重试复用原模型、词组、难度、题型和自定义输入，用户修改后才创建新参数。
- 刷新、离开和重连后从服务端恢复状态；客户端计时器不是事实来源。
- 历史记录保留成功和失败任务，允许删除记录，但删除不影响已经提交的练习记录，除非需求明确说明。

## 学习正确性

- 正确、错误、未作答、待判定和解析异常必须是不同状态。
- 答案反馈同时展示结果、正确答案、用户答案和必要解析。
- UI 重构不得改变题型、答案匹配、计分、文章分段或练习生成语义。
- 自定义粘贴内容有题目时先校验题型兼容；只有文章无题目时允许进入“AI 生成题目”路径，不伪装成已可练习。

## 可访问性

- 使用语义按钮、链接、表单标签、标题和列表。
- 所有功能支持键盘访问，焦点样式清晰，弹层正确管理焦点。
- 桌面和移动的主要触控目标至少 `44px`；不能只扩大图标而不扩大点击区域。
- 状态更新需要可被辅助技术感知，但避免把频繁进度更新全部朗读。
- 动画遵守 `prefers-reduced-motion`，禁用动画后仍保留状态变化。
