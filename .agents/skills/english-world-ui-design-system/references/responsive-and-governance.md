# English World 响应式与治理

## 目标视口

每个用户可见的 UI 变更至少覆盖：

- 桌面：`1440x900`。
- 宽桌面：`1920x1080`，确认工作区没有被旧的窄容器限制。
- 常用移动端：`390x844`。
- 最小移动端：`320x568`。

根据功能补充横屏、平板、软键盘打开、长文本、深色主题和大数据量场景。

## 桌面规则

- 延续 228px 展开侧栏、72px 收起侧栏、64px 上下文栏和 1560px 工作区。
- 工作型页面让主列表、表格和编辑区获得横向空间；聚焦任务保持约 1120/1080/860px 的内层宽度。
- 页面头部只保留任务标题、必要上下文和一个主要操作。
- 固定侧栏、上下文栏和主滚动区各自职责明确，不制造页面与内部容器双滚动。
- 宽屏不靠放大字体填空；使用稳定网格、合理列宽和内容密度。

## 移动端规则

- 移动端使用独立壳层和持久底部导航，不把桌面两栏简单缩小。
- 根壳层使用 `100vh` 回退和 `100dvh`，处理顶部、底部安全区。
- 一个页面只设一个主要纵向滚动容器。弹层打开后锁定背景滚动。
- 固定底栏、提交栏或浮动操作必须为内容预留等高 padding，不能遮挡最后一项。
- 输入聚焦和软键盘打开后，当前字段、错误信息和提交动作仍可见。
- 页面不得产生横向滚动。表格可转换为列表、分组行或受控横向区域，但整页不能溢出。
- 触控目标至少 44px，表单可编辑文字至少 16px。
- 长标题、用户名、英文单词和错误信息必须换行或受控截断。

## 桌面/移动能力对照

响应式验收先列出任务能力，而不是逐像素复制桌面布局：

| 能力 | 桌面 | 移动 |
|---|---|---|
| 浏览与筛选 | 表格、横向工具栏 | 列表、筛选弹层或紧凑控件 |
| 查看详情 | 页面、侧栏或 Drawer | 页面、全屏 Drawer/Popup |
| 创建与编辑 | 内联或工作面板 | 全屏表单或底部 Popup |
| 批量操作 | 多选 + 工具栏 | 多选模式 + 固定操作栏 |
| 通知 | 右上角铃铛 + Popover | 顶栏入口 + 全屏列表 |
| 长任务 | 列表状态 + 详情 | 列表状态 + 详情，允许离开恢复 |

两端应具备相同业务能力。若本次暂时无法实现某端，必须在需求、验收和结果中明确记录，不能静默隐藏。

## 实施工作流

### 1. 确认需求

- 写清用户、任务、开始状态、成功状态、失败状态和数据影响。
- 找到 PRD、专项规格或产品审计条目。
- UI 请求若隐含业务改动，先拆开并确认，不能在样式提交中混入。

### 2. 盘点现有模式

- 查找相邻页面、共用组件、主题 Token、桌面/移动实现和测试。
- 记录可复用模式与已知不一致。
- 判断现状属于正式标准还是迁移候选。

### 3. 作出设计决策

- 明确使用的布局宽度、组件、Token、主要操作、状态和响应式呈现。
- 优先扩展已有模式；需要新模式时说明为什么现有模式不足。
- 在动代码前定义 Loading、Empty、Error、Success、Disabled 和恢复路径。

### 4. 最小范围实现

- 保持业务逻辑和 API 契约不变。
- 只修改完成任务所需的组件和样式。
- 触及旧硬编码时迁移相关值到正式 Token，不顺手重写无关 CSS。
- 同步桌面和移动能力，或显式记录能力差异。

### 5. 验证

- 运行相关单元/组件测试和应用构建。
- 用真实浏览器验证正常、等待、失败、重试、刷新、返回和历史恢复。
- 检查 1440x900、1920x1080、390x844、320x568。
- 检查 Light、Dark 和至少默认 Blue Accent。
- 检查键盘、焦点、44px 触控目标、长文本、无数据和大量数据。
- 使用 `web-design-guidelines` 做最终规则复查。

## 渐进迁移

- 新页面和新组件必须直接遵守设计系统。
- 修改旧组件时采用“触及即整理”：只迁移本次需求涉及的颜色、间距、圆角、阴影和状态模式。
- 不为追求统一扩大到无关页面，不做混入业务改动的大型 CSS 清扫。
- 新增全局 Token 时同步更新 `theme.css`、明暗主题、ThemeProvider 映射、相关测试和本 Skill。
- 删除或替换旧模式前先用 `rg` 确认使用范围，避免影响移动端或隐藏页面。

## 规则例外

允许例外的条件：

1. 已确认需求需要不同模式。
2. 可访问性、浏览器限制或学习内容特性要求不同实现。
3. 已说明为什么现有 Token 或组件不足。
4. 已记录影响范围、回退策略和桌面/移动行为。

例外写入对应专项设计说明；单个页面的临时 CSS 不是新的项目标准。

## 设计评审清单

### 产品与内容

- [ ] 页面直接支持真实学习任务，没有营销式首屏。
- [ ] 中文操作文案清楚，英文只出现在学习内容或必要辅助位置。
- [ ] 主标题、主要操作和下一步唯一且明确。
- [ ] UI 改动没有改变题型、答案、计分、AI 生成或数据规则。

### 视觉与组件

- [ ] 使用正式 Token，Light/Dark 均可读。
- [ ] 间距、圆角、阴影和文字层级符合设计基础。
- [ ] 没有卡片嵌套、装饰性渐变、巨型文字或不必要浮层。
- [ ] 复用了 Ant Design / Ant Design Mobile 和已有图标。

### 状态与恢复

- [ ] Loading、Empty、Error、Success、Disabled 都有定义。
- [ ] AI 或长任务可以离开、刷新、重连和恢复。
- [ ] 失败显示原因、保留原参数并提供可执行重试。
- [ ] 危险操作说明影响范围并使用二次确认。

### 响应式与可访问性

- [ ] 目标桌面和移动视口无重叠、遮挡、截断或整页横向滚动。
- [ ] 固定导航和操作栏不会覆盖内容。
- [ ] 键盘、焦点、标签、Tooltip 和 44px 触控目标完整。
- [ ] 减少动态效果后任务仍可完成。

### 验证与交付

- [ ] 相关测试和构建通过。
- [ ] 浏览器验证覆盖正常、失败、重试和恢复。
- [ ] 桌面/移动能力差异已消除或明确记录。
- [ ] 设计系统例外和新增 Token 已同步文档。
