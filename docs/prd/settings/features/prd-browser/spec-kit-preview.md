## User Scenarios & Testing（用户场景与测试，必填）

### User Story 1 — 管理员安全阅读正式需求（Priority: P1）

作为管理员，我希望从管理端打开产品需求，按模块阅读正文与章节目录；未获得管理员权限的人不能通过直接访问链接读到内部需求。

**Why this priority**：内部需求可读和访问权限正确，是该功能可用的基础。搜索、导航等辅助能力也不能绕过此权限边界。

**Independent Test**：准备有效管理员、普通学习账号、匿名及失效管理员四种访问状态。管理员可打开需求，其他状态直接请求正文与资源均被拒绝；该阅读闭环可独立验证。

**Acceptance Scenarios**：

1. **AC-01/a**：**Given** 没有有效管理员登录，包含匿名、仅普通用户登录、管理员登录已失效，**When** 直接请求任一需求页面、深层链接或配套资源，**Then** 返回 401，响应不含受保护的需求内容。
2. **AC-01/b**：**Given** 管理员登录有效，**When** 请求已收录需求页面与必要资源，**Then** 可以读取对应内容。
3. **AC-02/a**：**Given** 管理员已登录，**When** 从管理端选择“产品需求”并打开一个模块的文档，**Then** 可以阅读正文与小节目录，文档保留原需求编号、状态和来源路径。

**关联要求**：FR-01、FR-02、FR-04。

### User Story 2 — 找到需求并沿引用继续阅读（Priority: P2）

作为管理员，我希望通过全文搜索找到具体需求，并点击文档引用或章节链接继续阅读，避免在多个文件之间手动查找。

**Why this priority**：在已经能安全阅读需求的基础上，搜索和链接降低定位成本；它们不改变需求内容或访问范围。

**Independent Test**：在测试需求集中放入一个明确的正文关键词、一条正式目录内文档链接及一个章节锚点。分别验证搜索、文档跳转和章节定位，不依赖在线编辑能力。

**Acceptance Scenarios**：

1. **AC-02/b**：**Given** 关键词出现在已收录文档正文中，**When** 管理员全文搜索该关键词，**Then** 能找到并打开包含该内容的需求。
2. **AC-03/a**：**Given** 当前文档含正式 PRD 范围内的相对文档链接和有效锚点，**When** 点击链接，**Then** 打开对应正文并定位目标章节。
3. **AC-03/b**：**Given** 目标文档不存在，**When** 尝试访问，**Then** 明确提示文档不存在；请求不能返回其他磁盘文件。
4. **AC-05/a**：**Given** 搜索输入为空或没有匹配项，**When** 管理员使用搜索，**Then** 显示明确状态与恢复入口，而不是空白页面或持续加载。空输入时展示全部文档还是提示输入，原文未规定，本稿不替它作决定。

**关联要求**：FR-02、FR-03。

### User Story 3 — 阅读一致的需求版本并从失败中恢复（Priority: P2）

作为管理员，我希望看到正式来源中已经同步交付的需求；发生加载失败或登录过期时，我知道如何重新进入阅读，且不会把需求批准状态误认成已开发或已上线。

**Why this priority**：来源明确和恢复路径让长期维护可持续，避免阅读副本与正式需求相互矛盾。

**Independent Test**：对照一次正式来源、交付快照和阅读版本，再分别模拟资源加载失败及登录过期，检查内容一致性与恢复入口。

**Acceptance Scenarios**：

1. **AC-04/a**：**Given** 本次发布产物已构建，**When** 检查公开前端产物与私有后端交付物，**Then** 公开产物不含正式 PRD 正文或搜索数据，私有交付物包含对应站点与来源快照。
2. **AC-05/b**：**Given** 文档加载失败，**When** 管理员查看阅读区域，**Then** 能看到失败提示及恢复入口。
3. **AC-05/c**：**Given** 管理员登录已经失效，**When** 尝试继续加载受保护内容，**Then** 访问被拒绝并提示恢复方式；重新登录管理端后，可以重新加载阅读器。

**关联要求**：FR-04、FR-05。

### Edge Cases（边界与异常）

| 情形 | 预期行为 | 需求依据 |
|---|---|---|
| 只隐藏菜单，直接打开正文或搜索索引 | 仍验证管理员权限，无有效登录则拒绝 | FR-04、AC-01 |
| 页面先前已经打开，随后登录失效 | 后续受保护请求拒绝，并提供重新登录后的恢复路径 | AC-01、AC-05 |
| 搜索输入为空或无匹配内容 | 展示明确状态与恢复入口；空输入的默认呈现待确认 | AC-05 |
| 需求页面加载失败 | 展示失败提示与恢复入口 | AC-05 |
| 文档不存在或请求试图越出目录 | 不读取任意文件，明确说明不可访问 | AC-03 |
| 用户看到 `final` 等需求状态 | 该状态不能被解释成开发完成、验收通过或已上线 | FR-05 |

**已有范围限制**：不增加手机入口，不提供在线编辑，不因格式整理自动部署。对未规定的体验指标和异常细节，不在本稿中擅自设定新的业务承诺。

## Requirements（需求，必填）

### Functional Requirements（功能要求）

下列父编号沿用正式 PRD；字母子项拆解原有复合要求，方便逐项映射验收和测试。

- **FR-01 — 入口与角色**
  - **FR-01.a**：系统必须在管理端提供“产品需求”入口，独立于公开文档中心。
  - **FR-01.b**：系统必须使用现有管理员权限；学习端不保留 PRD 入口。
- **FR-02 — 浏览与定位**
  - **FR-02.a**：管理员必须能够按正式模块索引浏览需求。
  - **FR-02.b**：管理员必须能够全文搜索并阅读需求正文与小节目录。
  - **FR-02.c**：阅读内容必须保留原需求编号、状态和来源路径。
- **FR-03 — 引用与只读边界**
  - **FR-03.a**：系统必须支持正式 PRD 范围内相对文档链接和章节锚点。
  - **FR-03.b**：本期需求阅读必须为只读，不提供在线编辑。
- **FR-04 — 全资源访问保护**
  - **FR-04.a**：系统必须对需求页面、深链、脚本、样式、搜索索引、哈希映射和其他资源逐次验证有效管理员登录。
  - **FR-04.b**：需求正文及搜索数据不得进入公开文档或公开前端产物。
  - **FR-04.c**：成功返回的受保护内容必须禁止缓存。
- **FR-05 — 来源与交付一致性**
  - **FR-05.a**：`docs/prd/` 必须保持为唯一维护来源。
  - **FR-05.b**：交付必须基于可验证的来源快照；来源更新后，必须显式同步、构建并随后端交付阅读版本。
  - **FR-05.c**：需求状态不得被当作实现、验收或发布状态。

### Key Entities（关键实体）

| 实体 | 含义与关系 |
|---|---|
| 产品模块 | 正式索引中的功能分组，关联该模块的 PRD 文档 |
| PRD 文档 | 正式来源中的需求正文，具有来源路径、需求状态与原需求编号 |
| 来源快照 | 一次待交付内容的来源记录，用于核对来源和阅读版本的一致性 |
| 受保护阅读产物 | 正文页面及搜索、导航等资源，均受同一管理员权限边界控制 |
| 管理员会话 | 现有管理员登录状态，决定能否读取受保护内容 |

实体描述用于理解业务数据，不在本稿中新增数据库表或存储要求。

## Success Criteria（成功标准，必填）

### Measurable Outcomes（可核验结果）

这些指标由已有 FR/AC 转述，用于评价需求是否被满足；不是本次执行结果，也不是新增的性能或转化率承诺。

- **SC-001 — 权限结果**：对页面、深链、脚本、样式、搜索索引、哈希映射及其他资源类别，匿名、普通用户和失效管理员的访问均被拒绝，不能获得需求内容；有效管理员可读取相同受保护内容。依据 FR-04、AC-01。
- **SC-002 — 阅读任务**：管理员可以完成“进入产品需求→按模块打开文档→全文搜索命中正文→沿引用打开文档→定位章节”这五个任务。依据 FR-01～FR-03、AC-02～AC-03。
- **SC-003 — 来源一致性**：本次交付范围内的文档都能对应正式来源及快照，展示的原需求编号、状态和来源路径得到保留；公开产物中不存在正文与搜索数据。依据 FR-02、FR-04～FR-05、AC-04。
- **SC-004 — 失败恢复**：空搜索或无匹配结果、加载失败和登录失效均有明确反馈；登录恢复后可重新加载阅读器。依据 AC-05。

## Assumptions（假设与依赖）

- **已确认约束，不是假设**：首期桌面管理端、使用现有管理员登录、只读、唯一来源 `docs/prd/`、采用 VitePress。
- **依赖**：正式模块索引可供构建导航；现有管理员登录机制能够判定登录有效与失效；发布流程能携带私有阅读产物。
- **未规定的量化指标**：原需求没有规定搜索响应时间、并发容量或用户完成任务耗时。本稿未虚构数值；若后续确有性能目标，需单独确认。
- **原需求待明确点**：AC-05 提到“空搜索”，但没有说明是空输入、无匹配结果还是两者。样例将两者列为审阅点，不擅自确定默认展示行为。
- **优先级说明**：P1/P2 是本稿为展示 Spec Kit 场景组织方式给出的整理建议，不改变原需求的交付范围，待用户审阅。
