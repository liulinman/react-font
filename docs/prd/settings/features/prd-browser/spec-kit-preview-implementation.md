# 实施约束对照：管理端产品需求模块

这是 [Spec Kit 结构样例](spec-kit-preview.md) 的配套对照，正式需求仍以 [prd.md](prd.md) 为准。以下全部来自已确认原文，不是新的技术选型或实施计划。

| 原条款 | 原有技术约束 | 在样例中的位置 |
|---|---|---|
| FR-02 | 使用 VitePress 展示正式需求 | 输入说明、已确认约束及本文件；浏览/搜索行为见 FR-02 |
| FR-04 | 后端逐次校验管理员登录后提供整个站点，包括 HTML、深链、JS、CSS、搜索索引、哈希映射与其他资源 | FR-04.a；AC-01/a～b |
| FR-04 | 不得复制到公开文档或公开前端静态目录；成功响应禁止缓存 | FR-04.b～c；AC-04/a |
| FR-05 | 从可验证快照构建私有 VitePress 站点，更新后显式同步、构建并随后端交付 | FR-05.a～b；SC-003 |
| AC-01 | 无有效管理员登录时返回 HTTP 401 | AC-01/a，未改成含糊的“提示登录” |
| AC-04 | 后端镜像携带私有站点与来源快照 | AC-04/a |
| AC-05 | 重新登录管理端后可重新加载阅读器 | AC-05/c |

## 本次做了什么

- 将一组连续 FR/AC 改为按优先级组织的用户场景、独立验证办法、Given/When/Then 场景、边界、功能要求、关键实体与可核验结果。
- 保留原父编号，增加子编号，用于逐项追踪；没有把子编号宣称为已经登记的测试 Case。
- 将产品行为和既有技术约束分开，同时保留对应关系。
- 明确原文未规定的指标，没有补写未经确认的时延、容量或完成率。

## 本次没有做什么

- 没有替换正式 PRD、修改正式功能索引或迁移其他模块。
- 没有安装 Spec Kit CLI、执行实现流程、同步后端快照或部署。
- 没有把原有测试通过或上线状态自动套给新拆分的验收场景。

## 审阅重点

1. 用户场景是否比原来的五条功能要求更容易阅读？
2. 细分验收是否便于后续逐项关联自动化测试？
3. 产品行为与实施约束分开后，是否仍能方便查回完整原要求？
