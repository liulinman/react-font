# 已发布阅读练习追加接收人

> 当前研发范围：电脑端学生端与管理端，按本功能实际角色适用。移动端仅作历史范围保留，不纳入当前设计、研发与验收；混合条款中的电脑端、业务及数据保护要求继续有效。历史“后续适配移动端”等计划不再默认启动。

## 背景与目标

### 背景与目标

老师首次发布时指定了学生，后续又需要将同一份练习发给其他学生。现有补发入口藏在“预览 → 反馈与纠错”，列表只显示预览、撤回、再生成，容易让老师误以为必须重新生成或重新发布。

在已发布练习列表直接提供“追加接收人”，让老师确认谁已经收到，再选择新增学生；已有作答、成绩、通知与练习版本均保持一致。

## 用户角色与使用端

当前适用端为电脑端学生端与管理端；角色权限以原条款为准。本次整理不新增使用角色或业务要求。

## 用户流程

### 使用流程

1. 老师点击已发布练习行的“追加接收人”，打开弹窗。
2. 弹窗显示练习标题、版本、已接收人数和用户列表（用户名、用户ID、作答状态），列表可翻页。
3. 老师搜索并多选新增用户；已接收用户显示“已接收”并禁选，停用用户不可新增。
4. 显示“本次新增 N 人”，按钮为“确认追加 N 人”；空选择或读取失败时不可提交。
5. 成功提示实际新增和因并发已接收而跳过的人数；刷新已接收名单、列表接收人数，并清空本次选择。老师可关闭或继续追加。

## 功能需求

### 功能要求

- FR-01：直接入口仅对已发布练习出现；草稿、生成中、失败、已撤回不可追加。
- FR-02：读取当前接收人及完成状态，不将最初发布配置误当成当前接收名单。无接收人显示空态，名单加载失败显示重试。
- FR-03：支持用户名搜索、多选和取消选择；保留跨搜索已选项；已有用户明确标识且不可选。最多每次1000人，延续现有接口限制。
- FR-04：重复用户、重复点击、响应丢失后重试不得重复创建分配或发送同一通知。相同请求重试返回同一追加统计，即使成功后练习被撤回或用户停用，也只返回原结果、不重新追加；选择变化使用新请求标识。提交期间禁止关闭和更换选择。
- FR-05：服务端对首次执行的请求再次核实练习状态和用户有效性；已成功请求重放先返回原结果。已停用/不存在用户使本次请求整体失败，保留选择并提示刷新；被并发追加的用户自动跳过并显示实际结果。
- FR-06：只追加同一已发布版本的分配，不修改文章、题目、评分修订、原有学生进度、原始成绩、批注或完成状态；新用户作答采用当前有效评分规则。
- FR-07：分配成功后进入现有通知投递机制；提示“已追加”，不将投递排队误称为通知已经送达。原有用户不重复通知。
- FR-08：原“反馈与纠错”里的补发控件替换为打开同一弹窗的入口，避免两种补发规则。

“已接收”指分配已创建，学生具备访问资格；不等同于通知已经送达。

## 权限与异常恢复

### 边界与权限

只有管理员可读取接收名单和执行追加；学生和匿名请求均拒绝。不提供移除接收人、重置作答、再次通知已接收人、自动分配未来新用户或批量多练习追加。

## 验收标准

### 验收条件

- AC-01：已发布练习列表一跳打开追加弹窗；已撤回行没有此入口。
- AC-02：原接收人A已提交，给B追加后接收人数+1；A的提交、成绩和分配ID不变，B可见同版本。
- AC-03：名单中显示A已提交且候选禁选A；搜索选择B和C后更换关键词仍保留选择。
- AC-04：未选择/加载失败不能提交；重复点击只发一个请求，网络失败保留选择，重试复用标识。
- AC-05：两名管理员同时追加B，B只有一份分配；各自提示的实际新增/跳过人数正确，同请求重放统计不变。
- AC-06：打开弹窗后练习被撤回，确认返回明确失败，不新增任何人；停用用户也整体拒绝。
- AC-07：成功后名单和列表刷新；后端或刷新失败有可恢复提示，不把成功追加当作未提交重新发送。
- AC-08：旧补发入口使用相同弹窗；桌面布局清晰，窄屏不横向溢出。

## 来源、决策与待决项

### 交付与验证

代码沿用现有鉴权、分配与通知体系，不需要数据库迁移。新增有意义的管理员组件测试、真实数据库并发/幂等/权限测试，以及浏览器“发布后追加”流程。以当前生产源码为基线保留线上独有功能，备份后发布；线上只读冒烟，不给真实用户发送测试练习。
