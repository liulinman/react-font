# 教师端课堂与阅读作业

## 背景与目标

Freewing 现有管理端支持新建或导入阅读材料、审核题目、预览和确认发布。发布对象可为全部用户或指定学生，操作由管理员权限保护。学生在「阅读练习 → 老师发的题」接收分配并作答。

教师需要在自己的入口中建立课堂，把入班链接分享给学生，随后按课堂布置阅读题。首期完成一条可验收的流程：教师建班 → 学生加入 → 教师审题并发布 → 学生找到作业、作答和查看解析。课堂提供稳定的发题对象，教师无需每次重新找人。

## 用户角色与应用范围

| 角色 | 使用端 | 首期任务 |
|---|---|---|
| 教师 | 独立电脑端 Web 应用，计划放在前端工作区 `apps/teacher/` | 创建并查看自己管理的课堂，分享入班链接，出题并发布 |
| 学生 | 现有学生 Web 端 | 通过链接登录后加入课堂，在「老师发的题」接收并完成作业 |
| 平台管理员 | 现有管理端 | 现有管理能力按既有规则使用。首期教师资格由谁开通、通过何种入口操作，待确认 |

`apps/teacher/` 是本草案采用的目录名。首期的建议边界为每个课堂一名所有者、每次发布选择一个课堂、学生可加入多个课堂。首期包括课堂作业成绩统计。协同教师、跨班批量发布、课程排期、移动原生端留待另议。

## 用户流程

1. 教师登录教师端，输入课堂名称并创建课堂。教师在课堂详情复制邀请链接，查看当前已加入的学生。
2. 已登录学生打开有效邀请链接后直接入班。未登录学生先走现有账号登录流程，成功后回到原邀请并直接入班。入班结果页展示课堂名称及「老师发的题」入口。
3. 教师在自己的课堂发起阅读练习。沿用现有管理端的「新建或导入 → 编辑与审核 → 学生预览 → 确认发布」流程。确认时展示课堂名称和预计接收人数。
4. 已分配的学生在「老师发的题」识别作业所属课堂，进入现有作答流程，提交后查看成绩和解析。教师可按作业查看本班提交进度与成绩。
5. 有学生晚入班时，教师可打开一份已发布的作业，选中尚未收到该作业的本班学生并确认补发。

## 功能需求

| 编号 | 要求 |
|---|---|
| FR-01 | 教师端提供独立入口。已开通教师资格的账号可进入，教师资格仅提供教师端授权。 |
| FR-02 | 教师可创建课堂。课堂名称必填，创建成功后出现在本人课堂列表。课堂详情展示名称、邀请入口、成员和阅读作业列表。 |
| FR-03 | 教师可复制课堂邀请链接，分享给学生。建议提供重新生成链接的能力，旧链接随即失效，已有成员继续保留。 |
| FR-04 | 已登录学生打开有效邀请链接后直接加入，无需教师审批或额外点击确认。未登录学生登录并返回原邀请后直接加入。重复打开链接或重复提交加入时显示已加入，同一学生在同一课堂只产生一条成员记录。无效或失效链接显示原因及联系老师获取新链接的提示。 |
| FR-05 | 教师可在课堂发起阅读作业，沿用管理端的编辑、审核、学生预览和确认发布流程。沿用现有阅读题型、内容有效性和答案校验规则。首期支持 PDF 和图片导入及 AI 出题，具体行为见 FR-10。 |
| FR-06 | 发布前展示课堂名称和预计接收人数。发布时重新核实教师权限、审核状态及课堂内有效学生。名单与确认时不一致时提示刷新并重新确认。课堂没有有效学生时保留草稿并阻止发布。 |
| FR-07 | 发布成功后，在教师端显示发布状态和实际接收人数。学生在「老师发的题」看到作业及所属课堂，继续用现有作答、提交、评分和解析流程。 |
| FR-08 | 教师重新打开草稿可继续编辑。处理失败展示可重试状态。发布响应丢失后，教师可刷新确认结果或重试同一次发布，已经成功的分配和既有通知不得重复产生。 |
| FR-09 | 教师可将本班仍处于已发布状态的历史作业手动补发给尚未收到的本班有效学生。确认前显示名单和人数。补发沿用同一作业版本，保留已有作答与成绩。重复操作或重试只产生一次分配，按实际新增人数反馈。 |
| FR-10 | 教师可上传 PDF 或图片导入阅读材料，也可使用 AI 生成阅读题。处理结果进入可编辑草稿，教师可核对文章、题目、答案和解析后审核发布。处理失败时保留可用的材料或草稿并提供重试入口。 |
| FR-11 | 教师可按本班已发布作业查看接收人数、已提交和未提交人数、平均分及学生成绩。补发成功后计入接收人数。平均分按有有效成绩的提交计算，未提交和无法评分的学生分别显示对应状态。 |
| FR-12 | 课堂提供班级群。老师和已入班的学生可发送文字消息并查看本班消息历史。班外账号无法读取或发送。发送失败保留草稿并支持重试，同一次发送只产生一条消息。 |

## 规则、权限与异常恢复

- **课堂归属。** 教师仅能访问自己管理的课堂、成员名单、作业草稿和发布状态。学生仅可查看自己有资格加入的邀请信息、本人入班结果和已分配作业。邀请页与学生端不展示班级成员名单。权限检查覆盖列表、详情及发布操作。
- **邀请。** 有效链接可用于多人直接入班，无需教师审批。老师重新生成链接时撤销旧链接。学生登录回跳时重新校验邀请，遇到失效链接时提示使用新链接并保留登录状态。默认有效期和成员退出或移除规则待确认。
- **发布对象。** 草案建议按确认后的当次有效成员分配。后加入的学生随班接收之后发布的作业。历史作业由教师按需手动补发。教师无法把课堂作业发给班外学生或全站用户。
- **作业状态。** 编辑和审核中的内容只在教师侧可见。发布成功以学生获得作答资格为准。若沿用站内通知，投递进度与作业分配状态分别展示。
- **恢复。** 无课堂、无成员、无作业、草稿加载失败、链接无效、名单变化及发布失败分别提供明确提示。刷新可恢复已持久化的课堂、成员和发布状态。
- **使用端。** 首期按电脑端 Web 验收。基本流程可使用键盘完成。教师侧只展示完成课堂操作所需的学生身份信息。

## 验收标准

| 编号 | 可观察结果 |
|---|---|
| AC-01 | 已开通教师资格的教师可建班并复制邀请链接。刷新后课堂仍可查看。普通学生无法进入教师端建班，教师资格本身不开放管理端权限。 |
| AC-02 | 已登录学生打开有效邀请后直接加入。未登录学生打开有效邀请，经现有账号流程登录后回到原邀请并直接加入。两条路径均无额外确认或教师审批，教师刷新后可看到入班学生。重复打开链接显示已加入，成员记录只有一条。 |
| AC-03 | 使用无效链接或已被替换的链接不能加入。重新生成链接后，已加入学生仍在成员名单中。 |
| AC-04 | 教师创建或导入阅读题，审核前不能发布，审核后可打开学生预览。无成员时发布受阻且草稿保留。 |
| AC-05 | 教师向含两名有效学生的课堂确认发布后，教师侧显示两名接收人，两名学生均可在「老师发的题」识别所属课堂并完成作答、提交及查看解析。班外学生看不到且无法通过作业直达链接访问。 |
| AC-06 | 教师 A 通过列表、直达链接或直接请求尝试访问教师 B 的课堂、成员或作业时被拒绝。 |
| AC-07 | 发布确认后成员名单变化时要求重新确认。同一发布已成功但客户端丢失响应时，刷新或重试显示实际发布结果，分配和既有通知均无重复。 |
| AC-08 | 学生晚入班时，旧作业尚未出现在其列表。老师选中该学生补发后，学生可作答同一版本。重复补发、班外学生及已撤回作业均无法新增分配，原学生的成绩和进度保持原值。 |
| AC-09 | 分别用 PDF 和图片导入材料，并执行一次 AI 出题。各自成功时结果进入可编辑草稿，教师审核前无法发布。处理失败时可查看失败状态并重试。 |
| AC-10 | 一份作业有两名接收人，其中一名提交并得 80 分时，教师看到接收 2 人、已提交 1 人、未提交 1 人及平均 80 分。补发给第三名学生后接收人数更新，原有成绩保留，其他班级的教师无法查看统计。 |
| AC-11 | 老师发一条消息后，本班学生可以看到并回复。老师返回班级群可看到回复。班外学生无法查看或发消息，失败重试无重复消息。 |

## 来源与待确认

用户已明确独立教师端项目、教师建课堂、学生通过有效链接直接加入且无需教师审批、老师用类似管理端的方式发阅读题，并提出班级群需要支持发消息。教师授权和班级可见范围是为新角色补充的草案规则，具体产品策略如下。

| 待确认 | 草案建议 |
|---|---|
| 教师账号从哪里来 | 沿用 Freewing 账号，由平台管理员开通教师资格。首期由谁操作及入口待确认。 |
| 邀请链接有效期与成员退出规则 | 默认有效期、学生能否主动退班和老师移除成员后的规则待确认。 |
| 管理端的其余能力 | AI 检查与自动修复、教师撤回和逐题统计是否纳入首期，以及补发通知规则，待确认。 |
