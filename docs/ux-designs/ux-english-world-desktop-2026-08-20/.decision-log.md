## 2026-08-20 — Product posture and default destination

- The desktop product must support two distinct but connected modes:
  - Learning workspace: focused execution of today's learning and review.
  - Vocabulary management: efficient search, editing, import, and maintenance.
- Fresh authenticated entry defaults to the **Today learning workspace**.
- Vocabulary management remains one primary-navigation action away and keeps its higher-density tool behavior.
- Direct links and browser navigation continue to land on the requested destination; the default does not override explicit routes.
- Rationale: vocabulary management serves the learning loop, while a learning-first default gives the product a clear identity and reduces the decision required to start a session.
- Source precedence for overlapping desktop decisions: 2026-07-28 over 2026-07-15 over 2026-05-22.

## 2026-08-20 — Primary product journey

- The canonical session starts in the Today learning workspace: understand today's load, begin the next recommended task, and finish the learning loop with minimal setup.
- Vocabulary Library, AI Query, Memory Map, and related tools are supporting management workflows reached from the learning context or the primary sidebar, not competing home destinations.
- A secondary power-user journey remains first-class: bulk-organize vocabulary, select material, launch practice, and inspect results without losing filters or working context.
- Navigation and visual hierarchy must make the relationship explicit: learning is the product's purpose; management is the efficiency layer that supports it.

## 2026-08-20 — Visual direction A presented

- Artifact: `.working/english-world-desktop-direction-a.html`.
- Direction name: Learning-first dual-mode workspace.
- Key-screen coverage: Today dashboard, Vocabulary Library, focused Review, and notification inbox overlay.
- Deliberate hierarchy: one primary action per page, compact supporting controls, low-distraction learning surfaces, and denser management surfaces within the same shell.
- Status: awaiting user review; no visual token or layout decision is approved by this artifact alone.

## 2026-08-20 — Tablet scope added

- User accepted the overall learning-first direction and requested appropriate tablet support.
- Form factor is now desktop Web plus adaptive tablet Web; the independent mobile product remains out of scope.
- Proposed tablet behavior:
  - Landscape uses a compact navigation rail while preserving efficient two-column layouts where content allows.
  - Portrait uses a single primary content column; dense vocabulary tables become expandable touch-friendly rows.
  - Primary tap targets are at least 44 × 44 CSS pixels and no essential action depends on hover.
  - Filters, scroll position, selection, and task progress survive orientation and detail-view transitions.
- Artifact: `.working/english-world-tablet-adaptation.html`.
- User rejected the first portrait treatment. The persistent dark navigation rail consumed scarce width, created an oversized empty visual block, and made the result feel like a compressed desktop page.
- The first portrait treatment is retained only as a rejected exploration; it must not be implemented.

## 2026-08-20 — Tablet portrait revision V2

- Artifact: `.working/english-world-tablet-portrait-v2.html`.
- Portrait removes the persistent side rail entirely.
- Primary destinations move to a five-item bottom navigation: Today, Learn, Vocabulary, Data, and More.
- AI Query, Memory Map, Settings, and other secondary destinations live under More in portrait.
- The top app bar retains product identity, global search, notifications, and account access.
- Vocabulary content receives the released width; rows remain touch-friendly and readable without horizontal scrolling.
- Landscape keeps the sidebar family because width permits it; responsive consistency is behavioral and visual, not a mechanically identical navigation placement.
- Status: approved by the user.

## 2026-08-20 — Approved visual baseline

- The learning-first dual-mode desktop direction is accepted as the baseline.
- Tablet portrait V2 is accepted as its adaptive portrait treatment.
- Desktop and tablet-landscape navigation remain sidebar-based; tablet portrait uses top app bar plus bottom primary navigation.
- The rejected portrait rail experiment remains excluded from all downstream specifications and implementation plans.
