## Scope Decisions

- Deliver an iOS-oriented PWA for personal use.
- Preserve the existing desktop Web UI unchanged.
- Bring every existing desktop capability to a dedicated mobile UI; no mobile route may fall back to a desktop layout.
- Use an independent `/mobile/*` route tree and share API contracts, domain rules, query logic, and learning state machines with desktop.
- Keep `/englishWorldMobile` as a compatibility redirect.
- PWA opens at `/mobile` and updates from the deployed Web build; no App Store, TestFlight, or native wrapper.

## Platform Decisions

- iPhone portrait is primary; landscape must remain usable without becoming a desktop layout.
- Support narrow widths from 320px through current large iPhone widths.
- Eliminate tap, double-tap, and input-focus layout zoom.
- Inputs and editable controls use at least 16px text.
- Keep intentional pinch zoom for images and long-form content.
- Respect top and bottom safe areas, dynamic viewport height, software keyboard, reduced motion, light/dark mode, and 44pt minimum targets.

## Visual Decisions

- Direction: iOS-native, restrained, system-font, grouped-list visual language.
- Avoid the immersive starfield treatment inside the application workspace.
- Use semantic system-like colors and shallow tonal hierarchy; decoration never competes with learning content.
- Loading skeletons match final geometry; modal stacks are never deeper than one layer.

## Information Architecture Decisions

- Four primary tabs: `学习`, `词库`, `工具`, `我的`.
- `学习`: search-first home, recent words, quick add/import, daily review, learning cockpit.
- `词库`: search, filters, compact list, word detail, add/edit, images, notes, mastery.
- `工具`: AI word query, Context Lab, IELTS core, memory map, statistics, bulk import, overwrite statistics.
- `我的`: account, in-app notification center, system settings, appearance, PWA status.
- System push notifications are not part of v1; preserve the in-app notification center and unread badge.

## Key Surface Decisions

- Home: search-first. Large search, manual add, AI completion, bulk import, and recent words appear before daily review.
- Word library: compact list plus independent detail page. Swipe actions have equivalent visible/menu actions.
- Review: one question per full-screen stage with a bottom safe-area action region.
- Context Lab: drill-down pages for task list, creation, reading, answering, results, and attempts. Never squeeze the desktop split workspace onto mobile.
- Forms: full-screen edit for complex data; bottom sheet for filters, pickers, and confirmations.

## Offline and Update Decisions

- Lightweight offline only: cache the shell and recently viewed read-only data.
- Persist unfinished forms, review answers, and Context Lab progress in IndexedDB.
- AI, refreshed statistics, and creation of new server tasks require connectivity and state that clearly.
- Do not automatically replay destructive mutations such as delete or overwrite.
- Download application updates in the background, but never force refresh while the user is typing or learning.
- Clear user-scoped offline business data on logout.

## Architecture Decisions

- Split the current large mobile component into route-level feature modules under a shared `MobileAppShell`.
- Desktop retains Ant Design; mobile uses Ant Design Mobile and mobile-specific composition.
- Shared business/domain modules must not import either desktop or mobile UI libraries.
- React Query remains the server-state layer; IndexedDB holds resumable local drafts and persisted recent query data.
- Service Worker caches static application assets and the offline shell, not arbitrary mutation responses.

## Verification Decisions

- No formal physical-device test requirement.
- Automated viewports: 320, 375, 390, 393, and 430px plus representative landscape dimensions.
- WebKit E2E covers every mobile route and the primary create/read/update/delete paths.
- Contract checks cover no horizontal overflow, 16px editable text, 44pt targets, safe-area reservation, and keyboard-safe actions.
- Preserve all existing desktop tests and add a desktop-to-mobile capability matrix.
- Validate manifest, service worker, install start URL, offline fallback, update deferral, and route deep links.
