# 学习工作区体验审视

2026-10-27，范围：用户提供的精读、词库和知识笔记截图及对应当前源码。本轮仅设计/隔离原型，不改线上页面。

## 主要问题及改法

| 问题 | 用户受到的影响 | 改法 | 优先级 |
|---|---|---|---|
| 精读单独硬编码绿色主题，另外两页沿用全站蓝灰；组件边界不一致 | 切页像进入另一个产品，重要状态与装饰色难区分 | 保留Freewing品牌，统一中性色、蓝色操作语义、字号/按钮/间距；阅读正文回到高对比墨色 | 高 |
| 精读默认目录、正文、笔记三栏，加上外层窗口，多个滚动条同时存在 | 阅读可用宽度被固定占用，滚动焦点难预测 | 默认正文+轻工具栏，目录按需打开，笔记按需作为侧面板；专注模式隐藏全局导航 | 高 |
| READ CLOSELY英文装饰、宽松大标题区、正文偏粗偏大 | 内容开始太晚，第一屏只有很少正文，像展示页 | 删除装饰文案，缩短标题区域，正文18px起、常规字重、约70ch行宽，保留字号调节 | 高 |
| 词库筛选卡片、列表卡片、展开笔记卡片层层嵌套，行上操作大量并列 | 视觉噪声多，笔记一展开就把后续词条推出视野 | 搜索与表格铺平；词条笔记在右侧上下文面板打开，保留列表位置；低频编辑/删除收进详情 | 高 |
| 单词、音标、词性、类型、状态、图片占独立列，但部分信息重复/为空 | 横向空间被消耗，释义与内容让位给低价值字段 | 单词与音标合并，词性靠近释义；本轮原型不常驻空图片列，不取消未来图片查看能力 | 中 |
| 开始学习/手册等批量操作在未选择时常驻且禁用 | 用户不知道先做什么，按钮越多越不清楚 | 先展示搜索、筛选、添加；选择词条后出现批量操作和明确数量 | 高 |
| 笔记列表直接铺长正文，标题、摘要、分类、日期密度接近 | 扫描困难，打开/返回切换成本高，屏幕宽但难比较 | 文件夹—短列表—正文并排，摘要只一行；单击阅读，显式编辑；窄屏再切换列表与正文 | 高 |
| 文件夹名截断、当前位置不够清楚；返回后的上下文易丢 | 需要重新寻找刚才的文件夹、条目或滚动位置 | 选中状态稳定，正文显示完整文件夹；实现时保留folder/note URL、搜索与列表位置 | 中 |
| 原文“关联”动作不够明确，保存/未保存没有稳定位置 | 用户不确定是否能回到原句，离开是否丢输入 | 明确“定位原文/查看关联词条”，稳定保存状态，未保存离开保护 | 高 |

## 空间原则

- 页面只保留一个主要滚动区域；长内容的上下文面板只在打开时独立滚动。
- 管理型内容可横向铺开；阅读型内容保持适合的行宽，留白用于读懂内容，不无限拉长每行。
- 内容以分隔线分组，主要版面不套大卡片，不用阴影、彩色标签替代信息层级。
- 蓝色只用于主要动作、选中和焦点；语义状态另有克制区分，不能只靠颜色表达。
- 深色是同一结构的适配，不重新发明一套组件；当前原型仅用于比较，尚未批准成为全站主题。

## 实现时必须保留

正文、段落ID、标注锚点与原件版本；词条/个人笔记/知识笔记的现有归属及关联；文件夹结构；保存失败恢复与未保存保护。不能为改布局重写或丢弃这些数据，也不能静默把用户内容重新生成。

原型单字段中英文搜索、批量入口位置、笔记阅读布局属于设计提案，未来需回写相应PRD/Spec及真实API契约后实现。本次没有修改正式功能、权限、主题持久化或生产数据。
