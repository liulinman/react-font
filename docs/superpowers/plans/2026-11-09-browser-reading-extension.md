# Chrome 阅读扩展实施计划

**目标**　从普通网页查一个英语单词在本句里的中文含义，并把本句和来源链接保存到当前用户的 English World 个人词库。

**设计依据**　[阅读扩展设计](../../design/vocabulary/browser-reading-extension/design.md)。[现有精读词卡需求](../../prd/intensive-reading/features/word-card/prd.md)提供可复用能力，扩展行为需单独登记为词库功能。

**当前状态**　实施计划草案。正式 PRD、Spec Kit 规格、代码和验收记录由对应任务产出。

## 1. 固化需求与验收

- 在 `docs/prd/vocabulary/` 登记浏览器扩展，关联精读词卡，不改其已有条款。冻结显式查词、先预览后收藏、引用持久化、已有词照常生成本句释义、账号隔离和失败恢复。
- 使用仓库固定的 Spec Kit 版本建立对应规格和任务，关联需求、设计和验收场景。前后端已有工作树包含其他改动，单独审阅和记录本次文件。

## 2. 接通后端

- 以独立的扩展端点复用 `ReadingWordLookupService` 的词形识别及 AI 释义，扩展路径对已收藏词也生成本句释义。查询只返回预览和收藏状态，保存使用服务端生成且与用户、语境和来源绑定的有效凭据。
- 独立引用记录保存词条归属、原文词、完整原句、词在句中的字符偏移、本句释义、HTTP(S) 来源地址、可选标题和保存时间。仅接受可安全打开的链接，拒绝携带用户名密码的地址，保留路径、文章查询参数和可用的锚点，按大小写不敏感的规则移除已识别的跟踪及凭据参数。URL 使用一次性签名或授权材料且清理后无法保留文章地址时，提示改用公开链接后重试。用 `/article?id=42&utm_source=news#section-2` 验证保留文章 ID 和锚点、移除跟踪参数，并覆盖含凭据的查询及片段。来源 URL 和标题不传给 AI。
- 使用数据库唯一约束保护同一词条下相同链接、原句和目标词位置的重试。词条与首次引用在同一事务中提交，引用绑定本人词条，跟随词条删除；已有词条和笔记不被覆盖。桌面详情按本人词条 ID 加载引用。
- 授权设计采用 English World 登录页发起的短时一次性授权码，绑定扩展回调、state 和 PKCE。扩展后台持有可撤销、限查词与收词的凭据。首次授权说明发送范围，用户同意后才发出首个含网页文本的请求。服务端确认账号和权限后再访问词库；扩展使用稳定 ID 约束本地调试回调。

## 3. 接通 Chrome 与词库详情

- 新建独立的 Manifest V3 扩展目录，右键入口按需注入。通过选区位置提取原句并标识当前词，页面的凭据输入、编辑区域、无可用正文或无法可靠提取完整句子时给出提示。查询把必要上下文及当前页的来源 URL、标题发给 English World 以生成绑定预览；只有确认保存时才将原句和来源持久化。
- 后台负责 API 与授权，网页注入代码只负责选区和词卡。词卡实现加载、失败、重试、重复收藏、已有词追加引用、关卡后忽略迟到结果。词库详情按设计展示引用列表和原文链接。
- 同步公开技术文档中的扩展安装、授权、查词和来源保存说明。

## 4. 验证

- 同词异义、词形变化和同一句里的重复拼写按当前选区判定。重点用 news / river 两个网页验证 bank 的两个释义。
- 覆盖新词、已有词、同句重试、并发保存、同一词多篇来源、刷新后的来源链接和跨账号隔离。拒绝过期或跨账号预览、非 HTTP(S) 来源和无权限凭据。
- 执行后端与前端检查，加载本地扩展在真实 Chrome 中操作，走完授权、查询、保存和词库回看。按项目验收入口保存当前运行证据，区分服务替身测试和真实 AI 验证。
