# English World 公用本地偏好存储设计

## 背景与目标

词库已经会通过 `localStorage` 记住用户选择的列表或卡片视图，但现有 `readWordLibraryView` 和 `writeWordLibraryView` 把存储访问、异常降级和值校验都写在词库专用文件中。以后增加其他本地偏好时会重复这些逻辑。

本次将公共行为封装为类型安全的本地偏好工厂，词库视图作为第一个使用方。不同偏好继续使用各自的键和值，不共享同一个选择结果。

## 公共接口

新增应用级公共工具 `createLocalStoragePreference<T>()`。调用方提供：

- `key`：稳定的 `localStorage` 键。
- `defaultValue`：缺失、无效或不可读取时的回退值。
- `isValid`：把存储中的未知字符串校验并收窄为 `T` 的运行时校验器。

工厂返回 `read()` 和 `write(value)`：

- `read()` 读取字符串并通过 `isValid` 校验；只有合法值才返回，否则返回默认值。
- `write(value)` 写入对应键。
- 两个方法都允许测试注入最小化的 Storage 接口，但生产环境默认使用 `window.localStorage`。
- 服务端或测试环境没有 `window`、浏览器禁止存储、配额已满或 Storage 抛错时静默降级，不阻断当前交互。

当前偏好值都是字符串，因此本次不引入 JSON 序列化、版本迁移、跨标签页同步或 React Hook。未来确实出现对象偏好时，再在调用方显式序列化，或根据实际需求扩展公共接口。

## 词库接入

词库保留 `WordLibraryView = "list" | "card"` 及其运行时校验器，并通过公共工厂声明一个偏好实例。`EnglishWorld` 使用该实例初始化状态并在切换时写入。

现有键 `english-world:word-library-view` 保持不变，因此已经保存的用户选择继续有效。默认值仍为 `list`，无效值仍回退到 `list`，存储失败仍不影响当前会话切换。

原词库专用文件保留为薄配置模块并导出 `wordLibraryViewPreference` 实例及 `WordLibraryView` 类型，避免把词库业务类型放进公共工具。该文件不再重复实现 Storage 访问和异常处理。

## 测试与验证

公共工具单元测试覆盖：

- 合法值能够读取。
- 缺失或非法值回退到默认值。
- 没有浏览器存储或读取抛错时回退。
- 合法值写入指定键。
- 写入抛错时不向调用方传播异常。

词库测试继续覆盖切换后写入现有键，以及重新进入页面时恢复卡片视图。最后运行相关 Vitest 测试、完整 English World 测试和生产构建。

## 非目标

- 不让不同页面共享同一个偏好值。
- 不改变任何界面或交互。
- 不修改后端接口、数据库或用户配置。
- 不迁移现有 storage key。
- 不顺带重构主题、侧栏等已有本地存储实现。
