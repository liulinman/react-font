# AI 阅读练习统一发布设计

日期：2026-10-12
状态：待用户审阅；本文件为设计，不表示功能已实现或部署。

## 1. 已确认的目标

用户希望后台借助 AI 生成一篇英语文章和配套题目，让用户独立作答，提交后展示正确答案及详细解析。用户已接受第一版采用“同一套题、每位用户独立作答”的方向。

完整流程：管理员配置 → AI 生成文章、题目、答案和解析 → 管理员预览发布或定时自动发布 → 用户收到练习通知并作答 → 提交后看到成绩和逐题解析 → 随时回看自己的记录。

前一阶段完成的后台布局、历史分页、发布确认和定时任务表单优化继续保留，目前仍未部署。不得覆盖工作区内其他未提交改动。通知列表样式已在先前任务部署，不应回退。

## 2. 第一版范围与默认值

以下是本次设计采用的默认值，用户可在审阅时调整：

- 练习以英语阅读为主：英文文章、英文题干与选项、中文解析。
- 默认 400 词、5 题、雅思 6.0 难度；可设置 200–800 词、3–13 题、雅思 5.0–7.5（0.5 步长）。
- 题型支持单选题和 True / False / Not Given；单选题可覆盖细节、推断、主旨和语境词义。暂不加入自由作文、口语评分和开放填空。
- 每题一项正确答案。各题等权，成绩为正确题数 / 总题数 × 100，保留整数；同时显示正确题数和总题数。
- 每人每套练习一次正式提交；提交后可以反复查看原文、答案及解析。第一版不加入重做排名、考试倒计时、截止日期或个性化出卷。
- 支持全部正常用户和指定正常用户。发布时固定接收人名单，新注册用户不会自动补发以前的练习。
- 手动生成默认审核后发布；定时任务可选择“生成草稿待审核”或“校验通过后自动发布”。
- 用户端同时覆盖桌面 Web 与移动端 Web；原生打包发布不包含在本次范围内。

## 3. 用户可见流程

### 后台：练习管理

在已优化的后台左侧新增“阅读练习”，保留公告发布与普通通知的用途。

- 列表展示标题、主题、难度、题量、状态、生成/发布时间、已提交人数 / 接收人数。
- “新建练习”填写主题/提示词、难度、文章长度、题型、题量和接收范围。
- 点击“生成草稿”立即返回任务状态，页面显示生成中。离开或刷新页面后可从列表继续查看。
- 生成完成后预览全文、全部题目、标准答案、中文解析和原文依据。
- 审核未通过可修改生成参数后重新生成新草稿；第一版不提供自由修改答案结构的编辑器。
- 发布前确认标题与接收范围；已发布的文章、题目、答案和解析固定不变。需要修改时生成新练习。
- “撤回练习”需确认：停止新的作答和提交；已经提交的用户仍能查看自己的历史结果。
- 失败状态显示可理解的原因与重试入口，不将占位文案当作有效练习发布。
- 草稿可删除；已有提交的练习保留记录，通过撤回/归档管理，不硬删除用户成绩。

### 后台：定时任务

为现有定时任务增加明确的“内容形式”：普通通知 / 阅读练习。学习主题预设不再承担内容形式的职责。

- 普通通知继续沿用现有行为。
- 阅读练习展示练习参数、接收范围、每天/每周/一次的时间配置，以及审核草稿/自动发布模式。
- 默认北京时间，重复任务明确标注时区；一次性时间转换为确定的 UTC 时刻。
- 每次运行生成一套新练习，所有接收人得到同一份内容。
- 任务列表可看到最近运行状态、失败原因和生成的练习入口。
- “立即执行”单独确认，视作一次人工运行，不无故移动下一次计划运行时间。

### 用户端：发现与作答

- 通知只包含练习标题、简短介绍和“开始练习”入口，不塞入全文、答案或解析。
- 新增“阅读练习”列表入口，标识待完成/已完成，通知不是唯一入口。
- 打开练习先看到文章、题量和难度，进入作答后可随时回看原文。
- 桌面采用文章与题目并排布局；窄屏采用文章/答题切换，显示作答进度。
- 刷新保留本机草稿，按用户和练习 ID 隔离；退出账号后其他用户不可读取。跨设备草稿同步不在第一版范围内。
- 未完成全部题目时，提示遗漏题并定位，不静默按错误提交。
- 提交时显示状态并阻止重复点击；网络失败保留答案，允许以同一提交标识重试。

### 提交结果

- 展示得分、正确题数、提交时间。
- 每题展示题干、自己的选择、正确答案、对错状态、中文解析和原文依据。
- 正确题同样提供解析；Not Given 题解释原文缺少什么信息，不伪造支持句。
- 刷新或以后重新打开仍能读取自己的成绩与完整解析。

## 4. 现有实现与方案选择

已核实：

- `nestjs/src/interface/notification/notification-ai.service.ts` 只生成通知标题与短正文，并有短文案 fallback，不适合作为试卷生成协议。
- `notification-scheduler.service.ts` 当前按分钟轮询，生成通知或通知草稿，尚无可直接用于 AI 试卷任务的持久化运行去重和失败恢复机制。
- `exercise-agent.service.ts` 已支持结构化文章和题目、个人生成任务、作答记录；现有提交逻辑包含提交后调用 AI 生成解析。
- `article-exercise`、`article-exercise-task`、`article-exercise-attempt` 以 `userId` 归属个人，不能直接将同一个个人任务 ID 发给所有用户。
- 桌面 Context Lab 和移动端阅读器已有阅读/答题/结果展示，可提取复用展示组件；不得放宽它们原有的用户归属校验。
- 通知响应目前不提供练习跳转字段，需要增加受限的结构化关联字段。

可选实现：

1. 给每个用户复制一套个人任务：接入表面较快，但重复存储、统一撤回和统计困难，容易破坏个人任务归属。
2. **采用共享试卷 + 独立接收人与提交记录（选定）**：复用模型客户端和展示组件，明确区分统一练习与个人 Context Lab。
3. 将全文和答案塞进通知：无法可靠实现答题、提交后揭晓、个人成绩，不采用。

## 5. 数据与状态

新增独立阅读练习模块，沿用项目已有 NestJS、Sequelize 和 MySQL 方式。

### 共享试卷 `reading_practice`

保存 ID、生成请求标识、参数快照、主题、标题、文章、题目及标准答案解析 JSON、接收范围配置、来源任务运行 ID、生成状态、发布时间、撤回时间和失败摘要。

状态：queued → generating → draft → published → withdrawn；生成失败进入 failed。自动发布也必须先通过与草稿相同的结构校验。

已发布内容不可原位修改。重新生成创建新 ID，避免成绩与答案错配。

### 接收与作答 `reading_practice_assignment`

唯一键 `(practiceId, userId)`；保存发放时间、可选的关联通知 ID，以及用于重试通知投递的状态。发布时写入接收人快照。

### 提交 `reading_practice_submission`

唯一键 `(practiceId, userId)`；保存提交请求标识、用户答案、分数、逐题批改快照和提交时间。标准答案必须从服务端已发布试卷取得，忽略客户端传入的评分字段。

重复提交同一请求返回原结果；已提交后发送不同答案不得覆盖原结果。并发提交依靠事务和唯一约束，而非仅靠按钮禁用。

### 定时运行 `reading_practice_run`

现有通知计划增加可选的内容形式和练习配置字段，旧数据默认普通通知。阅读练习运行记录保存计划 ID、计划触发时间或人工触发标识、状态、重试次数、领取租约及练习 ID。

定时运行唯一键 `(scheduleId, scheduledFor)`；人工触发使用独立请求标识。运行领取、失败重试和成功产物关联持久化。

## 6. 生成、发布与可靠性

- 后台请求创建持久化生成任务并立即返回 ID，前端轮询状态，不让长 AI 请求绑定在一次页面请求上。
- 使用现有服务端 AI 客户端，新增阅读练习的严格 JSON 协议。生成阶段同时产出文章、题目、正确选项、解析和依据。
- 检查题量、唯一题目 ID、合法题型、非空且不重复的选项、答案下标范围、非空中文解析，以及引用是否出现在文章中。
- Not Given 使用“相关段落 + 缺失信息说明”，不强制声称原文有答案支持句。
- 对超长/缺项/不合法输出做最多一次修复生成；仍不合格则失败，不发布半成品。结构校验不能保证所有语义正确，因此手动流程默认管理员审核，自动发布为显式选择。
- 生成任务以租约领取并支持进程重启后的超时回收；最多三次运行尝试，记录脱敏错误摘要。一个任务失败不阻断其他到期任务。
- 发布事务固定试卷状态和接收人名单；每个接收人的通知关联唯一，失败后可以补投，不重复建试卷/重复发送。
- 通知投递由持久化 assignment 投递状态驱动重试；SSE 只用于及时提示，用户练习列表读取数据库，不依赖 SSE 收到才可访问。
- 普通通知流程保持兼容，不在本次顺带重写其所有调度逻辑。

## 7. 接口与权限边界

后台接口：

- `POST /admin/reading-practices`：创建生成任务；带幂等请求标识。
- `GET /admin/reading-practices`：服务端分页列表及状态。
- `GET /admin/reading-practices/:id`：管理员预览，包含答案解析。
- `POST /admin/reading-practices/:id/retry`：失败任务重试，必须处理并发和重试次数限制。
- `POST /admin/reading-practices/:id/publish`：确认发布，重复请求不重复发放。
- `POST /admin/reading-practices/:id/withdraw`：撤回。
- `DELETE /admin/reading-practices/:id`：仅允许未发布且未被运行 worker 持有的草稿/失败记录。
- 现有计划创建/列表/立即执行接口扩展可选练习参数，旧请求保持有效。

用户接口：

- `GET /reading-practices`：仅列出当前用户收到的练习及完成状态，分页。
- `GET /reading-practices/:id`：只返回文章、题干、选项、状态与自己的完成标识；字段白名单序列化。
- `POST /reading-practices/:id/submissions`：接收题目 ID 和选择、幂等请求标识，校验全题作答并在服务端批改。
- `GET /reading-practices/:id/result`：只返回当前用户已提交的结果。

提交前的任何用户响应、通知、SSE、前端缓存和资源都不包含 `correctIndex`、解析或答案依据。隐藏 DOM 不算隔离答案。

用户必须登录且属于该练习接收人；已撤回练习禁止新提交。读取已提交结果仍校验当前用户拥有记录，不暴露其他人的作答。

通知新增可选 `action: { type: 'reading_practice', practiceId }`，只返回允许的字段，前端映射到内部路由，不将任意后台 metadata 或 URL 原样透传。

## 8. 路由与集成

- 后台新增阅读练习管理组件与 API，沿用已优化的侧栏与确认交互。
- 桌面新增 `/englishWorld/reading-practices`、详情/作答与结果路由。
- 移动端新增 `/mobile/reading-practices` 及详情/结果路由，并在学习入口提供访问。
- 桌面与移动端通知根据当前设备入口跳转相应内部路由。直接打开通知链接时先登录，登录后返回目标。
- 共用题目、选项、结果展示尽量提取为无业务归属的组件；个人 Context Lab 继续使用原接口和授权。

## 9. 必须通过的验收

1. 管理员生成文章和题目，能在预览中查看完整答案解析。
2. 生成失败可见且不发送通知；重试、刷新不会意外生成重复发布。
3. 发布给两个用户后，两人获取同一文章和题目，但答案、成绩和本机草稿互不串用。
4. 提交前检查所有用户接口和通知，不出现标准答案、解析或依据。
5. 单选和 True / False / Not Given 均能作答并按标准答案确定性计分。
6. 提交后每题都有自己的答案、正确答案、中文解析和依据；刷新结果不丢失。
7. 漏题、未知题目 ID、越界选项、非接收人、其他人的结果请求被拒绝。
8. 连点提交、网络重试与并发请求只产生一条正式提交；不得覆盖原答案。
9. 定时草稿与自动发布模式分别符合配置；重复调度、进程重启和人工触发不会重复发放同一次运行。
10. 撤回停止新作答/提交，保留已提交结果；旧通知和个人阅读练习回归通过。
11. 桌面和窄屏能够完成发现 → 阅读 → 作答 → 提交 → 查看解析的全流程。
12. 数据库迁移、后端测试、前端测试、构建及浏览器验证全部完成后才进入发布阶段。

## 10. 发布与回滚边界

采用兼容性数据库迁移，先后端支持，再前端入口。发布前备份并记录当前前后端镜像；不得让旧前端请求失效。

生成/自动发布能力应可关闭。回退应用版本时保留新增数据表和用户提交，不通过删除表回滚。
