# PRD：English World 薄弱词语境修复闭环

## 0. 文档目的

本 PRD 面向产品、设计、前后端开发与测试，定义 English World 下一轮桌面端功能迭代。它建立在[市场研究](../../research/market-english-world-functional-iteration-research-2026-07-17.md)和现有 Focus Studio 设计之上，不重复技术实现细节；技术边界记录在同目录 `addendum.md`。

## 1. 愿景

English World 不应只告诉学习者“今天做了多少题”，而应帮助他确认一个真实错词是否已经能在语境里使用。当前产品已有定向复习、错词结果、AI 语境生成和每日路线，但这些能力是分开的，用户必须自己重新选词并判断下一步。

本次迭代把一次错误变成最短可验证闭环：复习结束后，用户一键用本轮前 3 个去重错词生成 2–4 分钟微语境；系统用明确的目标词映射给出简短反馈；次日 Daily Coach 再次优先安排这些词。产品由“功能集合”迈向“会记住用户学习事件的教练”。

## 2. 目标用户

### 2.1 待完成任务

- 当我完成一轮复习后，我想立刻知道哪些错误值得继续处理，而不是重新选词。
- 当我以为自己认识一个词时，我想用短语境确认我是否真的会用。
- 当 AI 给出反馈时，我想快速看到错在哪里和为什么，而不是阅读一大段泛化解释。
- 第二天回来时，我想优先检查昨天的不稳定词，并知道它为什么再次出现。
- 当 AI 或网络失败时，我不想丢失已完成的复习结果。

### 2.2 v1 非目标用户

- 需要完整课程体系的英语零基础学习者。
- 需要教师班级、作业管理和多人协作的机构用户。
- 以口语评分、写作批改或大型词书配置为首要任务的用户。
- 移动端专项用户；v1 优先保证当前桌面端体验。

### 2.3 关键用户旅程

**UJ-1：小林把本轮错词继续练到语境里。**

小林是准备六级的大三学生，已经登录并从“今天”进入一轮定向复习。提交后结果页显示 4 个错词。系统在主要修复动作旁提供“用错词做语境练习”，并说明会选择本轮前 3 个去重错词、约 3 分钟。小林点击后直接进入微语境等待态，不必再次输入单词。生成完成后，他阅读 120–180 词短文并完成 3 道题。每道错题只展示目标词、错误原因和一个对比例句。完成后结果页分开显示“语境通过”和“下一自然日复查”。微语境失败或页面刷新后，系统仍可根据复习回合标识恢复原结果。

**UJ-2：小林第二天先修复昨天的错词。**

小林下一自然日打开“今天”。Daily Coach 在首要任务中显示“昨日错词复查”，列出最多 3 个词并说明它们来自昨日答错记录；只有距离最后一次错误至少 8 小时的词才会出现。小林开始定向复习；这次的独立答题结果用于形成下一自然日保持证据，而不是沿用昨天的同日正确率。若昨天没有符合条件的错词，Daily Coach 保持现有薄弱词路线。

## 3. 术语

- **复习回合**：用户在 Recite 页面完成并提交的一组主动回忆题。
- **真实错词**：复习回合中后端记录为答错的词；不由静态等级或数组位置模拟。
- **修复词**：从当前复习回合的真实错词中按结果顺序去重后选出的最多 3 个词。
- **微语境**：围绕 1–3 个修复词生成的 120–180 个以空白分隔的英文 token 和恰好 3 道题，预计 2–4 分钟完成。
- **目标词**：一道微语境题明确验证的单词；每道题恰好一个目标词。
- **昨日错词**：按用户时区定义的上一自然日内，最后一次答案为错误且距当前请求至少 8 小时的真实错词。
- **语境通过**：用户在微语境中答对某个目标词对应的题；不等同长期掌握。
- **下一自然日复查**：在错误发生后的下一自然日、间隔 8–36 小时完成的独立复习回合。
- **核心闭环**：复习回合 → 修复词 → 微语境 → 次日复查。
- **复习回合标识（reciteSessionId）**：后端持久化复习回合的唯一 ID，用于恢复结果并关联后续微语境。
- **语境任务标识（contextTaskId）**：异步生成任务的唯一 ID；其请求快照保存来源复习回合标识与模式。
- **语境作答标识（attemptId）**：一次微语境提交的唯一 ID；同一任务可有多次、互不覆盖的作答。
- **合格错词结果曝光**：一个至少包含 1 个真实错词且成功展示微语境入口的复习结果页曝光，每个 reciteSessionId 只计一次。

## 4. 功能需求

### 4.1 复习结果到微语境

**描述：** 复习结果页使用当前回合的真实错词建立一个直接、可预期的语境入口，实现 UJ-1。用户不需要返回 Context Lab 重新选择来源。

#### FR-1：显示语境修复入口

当复习回合至少包含一个真实错词时，用户可以在结果页启动微语境。

**可测试结果：**

- 结果页有错词时显示“用错词做语境练习”按钮，并显示“约 3 分钟”。
- [ASSUMPTION: A-2 — 用户愿意在复习后继续投入约 3 分钟；由 SM-1、SM-2 验证。]
- 结果页全对时不显示该按钮，也不生成空任务。
- 原有“再练错词”和“回到今日路线”能力继续可用。
- 按钮具有明确图标、键盘焦点和可访问名称。

#### FR-2：确定性选择修复词

系统从当前回合真实错词中按结果出现顺序去重，并取前 3 个作为修复词。

**可测试结果：**

- 输入包含重复错词时只传递一次。
- 错词超过 3 个时只传递前 3 个，页面明确提示本次处理数量。
- 不传递答对词、空字符串或未知词。
- 刷新结果页后，系统可按 reciteSessionId 读取原回合结果，修复词选择保持一致。

#### FR-3：无二次配置进入微语境

用户点击入口后直接进入以修复词为来源的微语境状态。

**可测试结果：**

- Context Lab 能识别来源为复习结果和模式为微语境。
- 创建语境任务时必须携带 reciteSessionId；后端把它与模式持久化在任务请求快照中，并在详情和 SSE 响应中返回。
- 后端必须先确认 reciteSessionId 属于当前用户，再从该回合 history 按原结果顺序推导前 3 个去重错词；客户端传入词必须与服务端结果逐项一致，不一致返回 `MICRO_REQUEST_INVALID`，且不得创建任务。
- 不存在或非本人回合统一返回 404，不能通过错误差异探测其他用户回合。
- 用户无需再次选择熟练度、数量或复制单词。
- 微语境生成失败时，复习回合和结果不丢失；用户可通过 reciteSessionId 返回或刷新恢复结果页。
- reciteSessionId 不存在或不属于当前用户时，结果页显示“本次复习记录不可用”，并提供返回今日路线动作。

#### FR-4：恢复复习回合结果

用户可以通过 reciteSessionId 读取自己已提交的复习回合结果。

**可测试结果：**

- 接口返回回合统计和按原提交顺序排列的逐词结果。
- 非本人回合与不存在回合均返回 404，不泄露记录是否属于其他用户。
- 直接打开带 reciteSessionId 的结果链接、从 Context Lab 返回和页面刷新都得到一致结果。
- 记录按现有数据库保留策略保存；MVP 不在客户端复制答案到持久存储。

### 4.2 微语境生成与作答

**描述：** 微语境复用现有 Context Lab 的异步任务、SSE、历史和提交能力，但采用独立且严格的内容边界，实现 UJ-1。

#### FR-5：生成受限微语境

系统可以围绕 1–3 个修复词生成 120–180 个英文词的短文和恰好 3 道单选题。

**可测试结果：**

- 每个修复词至少在短文中以大小写不敏感的完整词或完整短语出现一次。
- 每道题包含稳定题目 ID、4 个选项、唯一正确答案和一个目标词。
- 3 个修复词时题目与词一一映射；2 个词时一个词映射 2 题、另一个映射 1 题；1 个词时 3 题均映射该词。
- 正文按空白分隔 token 计数；内容长度、题数或目标词映射不合规时，任务以 `MICRO_OUTPUT_INVALID` 失败，不落成功文章。
- 普通 Context Lab 保持现有长文模式，不受微语境约束。
- `mode` 必须从任务创建贯穿请求快照、后台 worker、Webhook 校验、详情、历史和 SSE；旧任务缺省为 `standard`。
- 微语境的修复词以服务端回合校验结果为唯一事实来源，任务创建后保存的是已验证快照。
- [ASSUMPTION: A-1 — 受限 AI 输出在结构校验下可达到 95% 可用率；由前 200 次生成验证。]

#### FR-6：显示低负担解释

用户提交后，系统对错误题提供与目标词相关的简短解释。

**可测试结果：**

- 判题结果始终可用；AI 解释失败不改变正确性。
- 错题默认展示错误原因和一个对比例句，总正文不超过 120 个中文字符；扩展信息可折叠。
- 正确题不展示冗长解释，只显示目标词已通过。
- 用户可以点击“整组再答一次”清空当前选择并复用同一文章和题目；每次提交创建新的 attemptId，初次结果不覆盖。
- 页面默认只突出最近一次作答；历史中仍可查看此前作答。SM-5 只比较首次作答与紧随其后的第一次重试。

#### FR-7：按目标词归因结果

系统只使用题目显式目标词计算微语境中的修复词结果。

**可测试结果：**

- 错题结果返回对应目标词。
- 不再通过题目序号取模或数组位置猜测单词。
- 返回的待修复词必须属于该任务的修复词集合。
- 语境通过与长期掌握在文案和数据语义上保持区分。

### 4.3 昨日错词次日复查

**描述：** Daily Coach 使用真实复习历史识别上一自然日的不稳定词，并把它们放在次日路线首位，实现 UJ-2。

#### FR-8：按用户时区识别昨日错词

系统可以根据用户时区查询上一自然日的真实错词，并去重返回最多 3 个。

**可测试结果：**

- 客户端优先传 `timezoneOffsetMinutes`，单位为“UTC 到本地时间需增加的分钟数”，合法范围 `[-720, 840]`；新字段缺失时兼容合法的旧 `timezone` 小时字段。新字段存在但非法时不尝试旧字段，统一回退 `480`（中国标准时间）并记录警告；二者都缺失或旧字段非法时也回退 `480`。
- 日期边界支持正负偏移、半小时偏移和跨 UTC 日期；每次请求使用当时偏移，不推断夏令时规则。
- 同一词昨日多次作答时，以昨日最后一次作答结果为准；最后一次已答对则不再属于昨日错词。
- 昨日错词按最后错误时间降序、history id 降序稳定排序；距离当前不足 8 小时的词暂不返回。
- 只读取当前用户记录，不混入其他用户数据。
- 没有昨日记录时返回空集合，不使用模拟错词填充。

#### FR-9：昨日错词成为首要任务

当存在昨日错词时，Daily Coach 首要行动为“昨日错词复查”。

**可测试结果：**

- 行动说明包含入选原因和词数，携带准确 wordIds。
- 点击后进入现有定向复习流程，不新增一套答题页。
- 昨日错词同时可出现在薄弱词摘要中，并优先于仅由静态等级选出的词。
- 没有昨日错词时，Daily Coach 保持现有“开始今日复习”逻辑。

#### FR-10：区分同日结果与次日证据

产品文案和返回模型不得把微语境通过或同日重试称为长期掌握。

**可测试结果：**

- 微语境结果使用“语境通过 / 下一自然日复查”，不使用“已永久掌握”。
- 下一自然日复查是独立复习回合，保留新的提交时间和正确性。
- 只有间隔 8–36 小时的结果进入“下一自然日保持”分析；超出窗口仍可学习，但不计入该指标。
- 现有统计未实现该指标时，不展示伪造的“24 小时保持率”。

### 4.4 稳定性与可测量性

#### FR-11：核心流程可恢复

AI 生成或任务订阅失败时，用户可以恢复或退出，不丢失已提交的复习结果。

**可测试结果：**

- 生成失败显示可操作原因、重试和返回动作。
- 页面刷新后可通过 contextTaskId 恢复进行中或已完成任务，并可通过 reciteSessionId 返回原复习结果。
- 任务重复回调不创建重复结果。
- 普通复习提交不依赖微语境服务可用性。

#### FR-12：持久关联闭环与记录事件

系统持久记录不含答案正文或敏感文本的闭环漏斗事件。

**可测试结果：**

- 语境任务请求快照持久保存 reciteSessionId、mode 和修复词；提交记录已有 contextTaskId、attemptId 和结果，从而可查询复习回合 → 语境任务 → 词 → 下一自然日复查。
- 新增轻量 `learning_loop_event` 表与本人鉴权写入接口，记录普通复习开始/完成、合格错词结果曝光、微语境启动/生成成功/首次完成、次日复查启动/答对事件。
- 事件包含枚举 eventType、client flowId、eventUid、reciteSessionId、contextTaskId、attemptId、词数、耗时、时区偏移和状态，不包含用户答案、文章、题目或解释全文。
- `(userId, eventUid)` 唯一；客户端以事件类型和 flow/session/task/attempt 生成稳定 eventUid，重复请求返回原记录，不重复计数。服务端校验所有非空关联 ID 均属于当前用户且关系一致。
- 事件默认保留 180 天并写入 expireTime；账号删除时随用户数据删除，部署侧按 expireTime 定期清理。事件接口失败不得阻断复习、判题或结果恢复。
- [ASSUMPTION: A-4 — requestJson、wordsJson、attempt 与事件表足以建立唯一查询链；集成测试无法从曝光追到次日词级结果时停止发布。]
- [ASSUMPTION: A-5 — 轻量事件表能以可接受的写入成本提供 MVP 漏斗分母；用压测和重复写入测试验证。]

## 5. 非目标

- 不在本次建立完整 FSRS/SRS、稳定度或长期到期时间模型。
- 不重做 Context Lab 普通长文练习、PDF、历史和导入流程。
- 不重构 Memory Map 的全部模拟指标；只保证本次新增数据不依赖模拟归因。
- 不新增打卡、连续天数、通知、社交或排行榜。
- 不新增语音识别、口语评分、自由 AI 对话或写作批改。
- 不设计付费墙、额度售卖或广告。
- 不进行移动端专项重设计。

## 6. MVP 范围

### 6.1 范围内

- 复习结果页真实错词微语境入口。
- 通过 reciteSessionId 恢复本人复习回合结果。
- 确定性选择最多 3 个修复词。
- Context Lab 微语境模式与严格输出校验。
- 每题目标词映射、正确归因、简短解释与重试。
- 按用户时区识别昨日错词。
- Daily Coach 昨日错词首要任务及现有定向复习复用。
- reciteSessionId、contextTaskId、attemptId 与修复词的可查询关联。
- 失败恢复、回归测试和桌面端视觉一致性。

### 6.2 MVP 范围外

- 多日学习状态表和完整间隔调度：需先验证昨日闭环价值。
- 统一掌握度仪表盘：现有数据口径尚未统一。
- 移动端提醒和快速练习：桌面 MVP 通过后再适配。
- 口语或造句：需要新的质量与成本验证。

## 7. 成功指标

先部署事件采集但隐藏微语境入口，运行 7 天普通复习基线；再启用入口并运行至少 14 天 MVP。达到 200 个合格错词结果曝光且至少 60 个微语境首次完成回合后，可判断入口、完成和生成质量，但不能据此宣称学习效果。SM-3 仅作为探索性方向指标：处理组为来源复习后 30 分钟内完成最早微语境任务首次 attempt 的修复词；对照组为同期没有完成微语境首次 attempt、按原熟练度和过去 7 日正确率分层的真实错词。两组只纳入 8–36 小时内发生下一自然日复查的词；同一来源回合与词只取最早任务的首次 attempt。任何显著性或效果量结论必须先基于实际基线正确率、用户内聚类和目标最小效应完成 power calculation；达到计算样本前只报告样本量、置信区间和方向，不触发产品继续/停止决策。另行报告“任务创建/生成成功”的 intention-to-treat 方向指标。

**主要指标**

- **SM-1：微语境启动率** — `micro_context_started / eligible_wrong_result_viewed`，目标不低于 20%；每个 reciteSessionId 只计一次曝光。验证 FR-1 至 FR-3。
- **SM-2：微语境完成率** — `micro_context_completed / micro_context_started`，目标不低于 70%。验证 FR-5、FR-6、FR-11。
- **SM-3：下一自然日复查正确率变化** — 探索性报告处理组与匹配对照组的独立答对率差、95% 置信区间和样本量；完成 power calculation 并达到所需样本前不设 +5pp 上线门槛、不作因果宣称。验证 FR-8 至 FR-10、FR-12。

**次要指标**

- **SM-4：生成可用率** — 合规微语境任务数 / 微语境生成请求数，目标不低于 95%。验证 FR-5、FR-11。
- **SM-5：首次整组重试改善** — 同一任务第一次重试的正确词数减去首次作答正确词数；只保留首个重试 attempt。验证 FR-6、FR-7。
- **SM-6：下一自然日任务启动率** — 启动昨日错词复查的用户 / 收到该任务的用户，作为方向指标，不设上线门槛。验证 FR-9。

**反指标**

- **SM-C1：普通复习完成率下降不超过 2 个百分点** — 按同一 flowId 的 `recite_completed / recite_started` 比较基线与 MVP；超过则停止扩大流量并检查结果页负担。
- **SM-C2：生成耗时不得被当作学习参与** — 不用等待时长优化“活跃”。
- **SM-C3：同日正确率不得被当作长期掌握** — 防止指标口径误导。
- **SM-C4：AI 失败造成复习结果丢失必须为 0** — 任一确认案例均阻断发布。

**继续/停止决策**

- 继续增强：SM-1、SM-2、SM-4 达标且 SM-C1/SM-C4 未触发；SM-3 作为方向证据进入下一轮实验设计，不作为本轮发布门槛。
- 保留但优化入口：稳定性达标、SM-1 或 SM-2 未达标，先改文案/时机，不进入完整 SRS。
- 停止扩大：SM-C1 下降超过 2 个百分点、存在结果丢失、生成可用率低于 90%，或完成 300 个合格曝光后 SM-1 仍低于 10%。

## 8. 跨功能质量要求

- **性能**：微语境任务创建接口 p95 小于 1.5 秒（不含后台 AI 生成）；昨日错词查询 p95 小于 300 毫秒；前端等待 90 秒仍未完成时展示“仍在生成”与返回动作，不把任务误标为失败。[ASSUMPTION: A-3 — 现有相关索引可满足该查询边界；上线前用代表性数据验证。]
- **可靠性**：微语境任务重复 Webhook 不创建第二篇文章；普通复习不依赖 AI；任何已提交回合均可由 reciteSessionId 恢复。
- **隐私**：事件不记录答案、文章、题目或解释全文；生成输入仅包含修复词、mode 与 reciteSessionId；事件表只保留最小 ID、计数和状态字段，默认 180 天到期。
- **可访问性**：新增按钮可键盘操作，有可见焦点；状态不只通过颜色表达；遵守 `prefers-reduced-motion`。
- **兼容性**：现有普通 Context Lab、复习、词库、统计、历史和 API 默认行为不变。
- **可观察性**：失败日志包含 errorCode、userId、reciteSessionId、contextTaskId、stage 和 elapsedMs，不包含答案正文；至少区分 `MICRO_REQUEST_INVALID`、`MICRO_GENERATION_FAILED`、`MICRO_OUTPUT_INVALID`、`MICRO_TASK_NOT_FOUND` 和 `RECITE_SESSION_NOT_FOUND`。

## 9. 约束与护栏

- AI 只生成受限微语境和解释，不决定复习题的规则正确性。
- 所有推荐理由必须来自真实历史或明确静态规则，不展示模拟“近期错词”。
- 核心闭环不受付费、能量或广告阻断。
- 面向公众部署前由产品负责人和工程负责人共同完成发布检查：生成内容标识策略、传给模型的字段、数据库保留期限、结果删除入口、服务商数据条款和失败投诉入口；任一项未确认即阻断公众发布。
- 桌面视觉沿用现有 Focus Studio 设计令牌、按钮层级和简短动画。

## 10. 开放问题

无阻塞问题。多日 SRS、口语输出、统一掌握度和具体商业化阈值在 MVP 数据形成后再决策。上述实验门槛由本 PRD 直接采用，不再等待产品选择。
