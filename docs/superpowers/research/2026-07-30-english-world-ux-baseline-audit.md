# English World UX 产品审计

- 审计任务：验证 English World 核心学习旅程，并把体验缺口整理为可验收需求。
- 目标用户：使用桌面或手机完成词汇复习、语境练习和通知阅读的个人学习者。
- 前置条件：本地前后端运行；使用普通用户 `alin` 登录；已有成功、失败和处理中练习包。
- 开始状态：用户已登录，位于今日学习或移动端首页。
- 成功状态：用户可生成或恢复练习、完成作答并提交，失败后能按原意恢复，通知可回看。
- 设备与视口：桌面 `1440x900`；移动 `390x844`。
- 审计版本/提交：`36de5b9`。
- 已读规格与测试：移动 Context Lab、移动易用性、练习记录、Context Lab 工作区规格，以及相关 Vitest/Cypress 测试。
- 证据目录：`docs/superpowers/research/assets/2026-07-30-ux-audit/`。
- 未覆盖范围：真实断网、登录过期、屏幕阅读器实机、跨设备同时登录、生产数据规模和管理后台。

## EW-UX-001 未提交答案在关闭或返回后立即丢失

- 用户目标：分段完成一篇较长的语境练习，并在误触返回后继续作答。
- 复现步骤：桌面或移动端打开成功练习包，选择第 1 题答案，关闭弹窗或点击“返回”，再打开同一练习包。
- 当前结果：已选答案全部清空，离开前没有警告，也没有继续草稿入口。
- 预期结果：系统保留当前草稿；至少在无法保存时明确确认离开后果。
- 证据：
  - 浏览器观察：桌面和移动端均重复复现；截图见 `desktop-context-lab-practice.png`、`mobile-context-lab-practice.png`。
  - 代码/规格：`ContextLabPage.tsx:948-950` 和 `MobileContextLabPage.tsx:188-194` 每次打开都清空答案；移动规格虽排除离线草稿，但要求阅读流不能因关闭界面丢失位置。
- 证据类型：浏览器观察、代码证据、规格事实。
- 根因：作答状态只存于组件内存，离开动作没有保护或草稿生命周期。
- 严重度：P1
- 置信度：高
- 用户影响：长文练习的投入可能一次性丢失，用户需要从头作答。
- 产品影响：直接伤害学习闭环和对练习可靠性的信任。
- 发生范围或频率：两端；每次部分作答后关闭、返回、刷新或重新打开都会发生。
- 推荐需求：为未提交答案建立可恢复草稿；关闭、返回、切换任务和刷新前执行统一离开保护。
- 验收标准：
  - Given 用户已完成至少一题但尚未提交
  - When 用户关闭、返回或重新进入同一练习包
  - Then 系统恢复答案，或在离开前明确提示将丢失内容并允许取消
- 端范围：两端
- 依赖：练习包 ID、用户 ID、草稿过期策略。
- 非目标：本期不要求离线跨设备同步。

## EW-UX-002 移动端生成失败后没有原因和恢复动作

- 用户目标：理解生成为何失败，并保留当前意图快速重试。
- 复现步骤：在移动端进入 Context Lab，查看状态为“生成失败”的练习包。
- 当前结果：卡片只显示“生成失败”和“删除”，不显示 `errorMessage`，也没有重试。
- 预期结果：显示可理解的原因、下一步和按原参数重试入口。
- 证据：
  - 浏览器观察：`mobile-context-lab.png` 中多个失败卡片均只有删除操作。
  - 代码/规格：`MobileContextLabPage.tsx:739-774` 未渲染失败原因或重试；`2026-07-01-mobile-context-lab-sync-design.md` 明确把 retry/delete actions 纳入范围。
- 证据类型：浏览器观察、代码证据、规格事实。
- 根因：移动历史卡片只实现成功态动作和通用删除动作，失败态未进入产品状态模型。
- 严重度：P1
- 置信度：高
- 用户影响：AI 生成失败后核心任务中断，只能猜测原因并重新填写。
- 产品影响：失败样本较多时会显著降低生成成功感知和移动端可用性。
- 发生范围或频率：移动端所有失败练习包。
- 推荐需求：补齐移动端失败原因、可执行建议和原参数重试，并保留失败任务用于诊断。
- 验收标准：
  - Given 一个包含后端错误码或错误信息的失败任务
  - When 用户查看移动端任务卡
  - Then 卡片显示友好原因、下一步和“按原参数重试”
- 端范围：移动
- 依赖：统一错误码映射、原始生成参数可用。
- 非目标：不在客户端伪造成功内容。

## EW-UX-003 桌面“重新生成”可能生成另一份内容

- 用户目标：对失败任务执行语义真实的重试。
- 复现步骤：创建任务 A，修改左侧生成表单，再点击任务 A 的“重新生成”。
- 当前结果：按钮调用当前表单的 `handleGenerate`，不会恢复任务 A 的词源、词组、难度、模型或粘贴材料。
- 预期结果：重试默认使用任务 A 的原始参数；若参数不可用，应明确改为“用当前设置新建”。
- 证据：
  - 代码/规格：`ContextLabPage.tsx:896-915` 从当前 `requestBody` 创建任务；`ContextLabPage.tsx:2355-2365` 的失败卡片直接调用该函数。
  - 推断：用户在失败后调整过表单时，新任务内容会偏离原始意图。
- 证据类型：代码证据、推断。
- 根因：历史任务重试和新建任务共用无参数的表单提交函数。
- 严重度：P1
- 置信度：中
- 用户影响：用户以为在重试原题，实际可能得到不同词汇或不同文章。
- 产品影响：结果与用户意图不一致，且界面没有揭示这一变化。
- 发生范围或频率：桌面端失败任务；用户在失败前后改过表单时必现。
- 推荐需求：为任务保存可重放参数，并区分“重试原任务”和“用当前设置新建”。
- 验收标准：
  - Given 失败任务 A 与当前表单 B 参数不同
  - When 用户选择“重试原任务”
  - Then 新请求与 A 的可重放参数一致，界面展示参数摘要供确认
- 端范围：桌面
- 依赖：任务参数快照、粘贴材料引用保留策略。
- 非目标：不自动覆盖用户当前表单。

## EW-UX-004 实时状态订阅中断后用户不会知道

- 用户目标：等待异步生成时准确知道任务仍在运行、已失败或需要手动恢复。
- 复现步骤：生成标准任务后让 `/context-lab/task-events` 流结束或报错。
- 当前结果：订阅结束后不重连、不轮询，页面也没有持久错误状态；两端调用均未传入 `onError`。
- 预期结果：自动重连或轮询兜底，并把断连、重试和手动刷新放在任务附近。
- 证据：
  - 代码/规格：`server/learning.ts:101-141` 在流结束或异常后退出；`ContextLabPage.tsx:694`、`MobileContextLabPage.tsx:142` 只传更新回调。
  - 待验证：真实网络抖动下的发生率尚未测量。
- 证据类型：代码证据、待验证。
- 根因：标准任务缺少连接生命周期和恢复状态机。
- 严重度：P2
- 置信度：中
- 用户影响：任务可能长时间停在“处理中”，用户只能猜测并手动刷新。
- 产品影响：放大 AI 等待焦虑，也会制造重复生成。
- 发生范围或频率：两端网络中断、代理超时或服务重启时。
- 推荐需求：实现带退避的重连和详情轮询兜底，显示连接状态并防止重复创建。
- 验收标准：
  - Given 用户正在等待任务且事件流中断
  - When 自动重连尚未成功
  - Then 页面显示“状态同步中断”，自动尝试恢复，并提供刷新状态操作
- 端范围：两端
- 依赖：任务详情接口、重连上限与退避策略。
- 非目标：不要求事件流永久保持单连接。

## EW-UX-005 移动端刷新后丢失 Context Lab 工具状态

- 用户目标：刷新、收藏或分享当前移动学习工具，并回到同一任务上下文。
- 复现步骤：从移动首页进入“语境练习”，刷新 `?view=aiTool`。
- 当前结果：刷新后回到“AI 单词查询”，而不是 Context Lab。
- 预期结果：URL 能表达当前工具，刷新和前进后退可恢复相同状态。
- 证据：
  - 浏览器观察：直接访问 `?view=aiTool` 后，DOM 快照显示默认选中“AI 单词查询”，URL 未包含 Context Lab 子状态。
  - 代码/规格：`EnglishWorldMobile.tsx:124-141` 只把一级 `view` 写入 URL，`activeToolTab` 固定从 `word` 初始化。
- 证据类型：浏览器观察、代码证据。
- 根因：二级工具状态由本地 state 保存，未进入路由模型。
- 严重度：P2
- 置信度：高
- 用户影响：刷新和返回路径不可预测，无法稳定收藏语境练习入口。
- 产品影响：削弱移动端任务连续性和可分享性。
- 发生范围或频率：每次刷新、直接打开或新标签访问。
- 推荐需求：让移动端 URL 同步一级视图和二级工具，并定义非法参数降级行为。
- 验收标准：
  - Given URL 指向移动 Context Lab
  - When 用户刷新或直接打开该 URL
  - Then Context Lab 保持选中，浏览器前进后退也恢复正确工具
- 端范围：移动
- 依赖：移动路由参数规范。
- 非目标：不要求把未提交答案直接编码进 URL。

## EW-UX-006 桌面提交后答案可改但解析仍是旧结果

- 用户目标：明确区分“已提交结果”和“开始新一次练习”。
- 复现步骤：桌面端完成提交，结果和解析出现后修改任一选项。
- 当前结果：选项仍可编辑，提交按钮仍显示，但原解析和得分不随答案变化。
- 预期结果：提交后锁定本次答案；若允许再次练习，应以明确的新 attempt 开始。
- 证据：
  - 代码/规格：`ContextLabPage.tsx:1837-1867` 的 `Radio.Group` 未按结果禁用，提交按钮始终存在；移动端在有 `submitSummary` 时会禁用答案。
- 证据类型：代码证据。
- 根因：桌面端没有明确的 attempt 生命周期状态，展示答案和已提交结果共享同一可变状态。
- 严重度：P2
- 置信度：高
- 用户影响：屏幕上的当前答案可能与得分和解析不匹配。
- 产品影响：降低学习反馈正确性的可信度，并造成两端行为不一致。
- 发生范围或频率：桌面端每次成功提交后。
- 推荐需求：提交后锁定当前 attempt；用明确动作开始新一次练习并清理旧结果。
- 验收标准：
  - Given 一次练习已提交并显示结果
  - When 用户查看题目
  - Then 答案不可直接修改，且“再练一次”会创建新的本地作答状态
- 端范围：桌面
- 依赖：attempt 语义和重复提交规则。
- 非目标：不改变已有历史记录数据结构。

## EW-UX-007 练习和通知历史被静默截断

- 用户目标：找到较早的练习包和公告，恢复长期学习记录。
- 复现步骤：账户拥有超过当前首屏限制的练习包或通知，再搜索或滚动列表。
- 当前结果：桌面练习固定请求前 10 条，移动固定前 20 条，通知固定前 20 条；没有分页或加载更多。
- 预期结果：用户可继续加载，搜索统计基于完整结果。
- 证据：
  - 代码/规格：`ContextLabPage.tsx:609-612`、`MobileContextLabPage.tsx:123-126`、`NotificationContext.tsx:72-76` 固定首屏数量；对应页面无翻页入口。
- 证据类型：代码证据。
- 根因：接口已经支持分页游标，但用户端只实现首屏快照。
- 严重度：P2
- 置信度：高
- 用户影响：旧练习和重要公告看似消失，无法回看或恢复。
- 产品影响：历史价值随使用时长下降，活跃用户最先受影响。
- 发生范围或频率：练习超过 10/20 条或通知超过 20 条后持续发生。
- 推荐需求：为练习和通知提供分页或加载更多，展示完整结果计数和加载结束状态。
- 验收标准：
  - Given 账户有 25 条通知或练习记录
  - When 用户加载下一页
  - Then 可访问第 21 至 25 条且不会重复或丢失实时新增记录
- 端范围：两端
- 依赖：分页、游标与实时插入的合并规则。
- 非目标：不要求一次性渲染全部历史。

## EW-UX-008 粘贴文章任务在历史中可能没有可识别标题

- 用户目标：在多个自带材料之间找到刚才上传的文章练习。
- 复现步骤：粘贴一篇没有独立词表的文章并生成任务，回到历史列表。
- 当前结果：历史标题仅取 `task.words`，词表为空时会显示空标题和“0 个词”。
- 预期结果：每个材料任务有稳定、可区分的标题和来源摘要。
- 证据：
  - 代码/规格：桌面 `ContextLabPage.tsx:2335-2343`、移动 `MobileContextLabPage.tsx:747-755` 都以 `task.words` 构建标题；粘贴模式允许文章本身作为输入。
  - 待验证：当前本地样本中尚未创建空词表粘贴任务。
- 证据类型：代码证据、推断、待验证。
- 根因：任务身份模型仍以词表为中心，没有材料标题字段或回退规则。
- 严重度：P2
- 置信度：中
- 用户影响：用户无法从历史区分自己的文章，尤其在反复练习时。
- 产品影响：削弱“自带文章练习”功能的可持续使用价值。
- 发生范围或频率：粘贴文章且后端未提取词组时。
- 推荐需求：为材料任务生成可编辑标题，并保留来源类型、创建时间和内容摘要作为回退。
- 验收标准：
  - Given 粘贴文章任务没有词表
  - When 任务出现在桌面或移动历史
  - Then 卡片仍显示非空、可区分且两端一致的标题
- 端范围：两端
- 依赖：任务标题字段或确定性回退算法。
- 非目标：不要求 AI 每次都生成标题。

## EW-UX-009 移动端能收到通知 Toast 但无法回看收件箱

- 用户目标：错过实时提示后，在手机上重新查看公告和高频词通知。
- 复现步骤：移动端登录后打开“更多”，查找通知入口。
- 当前结果：全局 Provider 可显示实时 Toast，但移动导航和“更多”没有通知铃铛或收件箱入口。
- 预期结果：移动端提供未读数量、通知列表、已读和全部已读能力。
- 证据：
  - 浏览器观察：`mobile-more.png` 中没有通知入口。
  - 代码/规格：`NotificationContext.tsx:137-146` 全局接收并弹 Toast；`NotificationBell.tsx` 仅挂在桌面 `EnglishWorldContextBar`；`MobileMorePage.tsx` 无通知项。
- 证据类型：浏览器观察、代码证据。
- 根因：通知数据层全局化，但收件箱展示层只接入桌面布局。
- 严重度：P2
- 置信度：高
- 用户影响：用户错过短暂 Toast 后无法在手机找回公告。
- 产品影响：定时内容和重要公告在移动场景中的触达闭环不完整。
- 发生范围或频率：所有移动端通知；用户未立即阅读时。
- 推荐需求：在移动端提供通知入口和与桌面一致的收件箱能力。
- 验收标准：
  - Given 用户有一条未读通知
  - When 用户在移动端打开通知入口并阅读
  - Then 可查看正文、未读数减少，刷新后状态保持一致
- 端范围：移动
- 依赖：复用现有通知 Context 和 API。
- 非目标：不要求移动端采用桌面抽屉布局。

## EW-UX-010 移动端关键交互对键盘和触控发现不友好

- 用户目标：通过键盘、辅助技术或明确触控操作进入学习工具并标记生词。
- 复现步骤：键盘导航移动首页卡片和底部导航；在文章中寻找“标记生词”入口。
- 当前结果：首页学习卡片是无角色的 `div` 点击区；底部导航把 `role=tab` 放在内部标题而非真实交互容器；标记生词只监听 `contextmenu` 隐藏手势。
- 预期结果：可点击入口具备正确语义、焦点和键盘行为；触屏标记动作有可发现路径。
- 证据：

- 置信度：高
- 用户影响：键盘和辅助技术用户无法可靠进入功能，普通触屏用户也难发现生词标记。

- 推荐需求：把导航和卡片改为真实按钮/链接语义；为文本选择提供触控可发现操作并保留长按快捷方式。
- 验收标准：
  - Given 用户只使用键盘或屏幕阅读器
  - When 导航移动首页和底部导航
  - Then 每个入口可聚焦、可激活并报告正确名称与选中状态
  - Given 用户在触屏文章中选择文本
  - When 选择完成
  - Then 页面显示可发现的标记、翻译和导入操作
- 端范围：移动
- 依赖：移动组件语义支持、触屏选区兼容测试。
- 非目标：不改变文章正文视觉风格。
