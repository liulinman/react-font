# iPhone 个人安装版

前端资源打包在应用内，接口连接 `http://124.223.157.129/api`。使用 React + Capacitor 8；Xcode 26 或更新版本、Node 22 或更新版本；最低 iOS 17。HTTP 服务尚未加密，当前仅对该 IP 设置 ATS 例外，有 HTTPS 地址后应更新 `.env.ios` 并重新打包。

## 安装到自己的 iPhone

首次克隆后，在此目录创建本地 `.env.ios`，设置 `VITE_API_BASE_URL=http://124.223.157.129/api`（或自己的接口地址）。该环境文件仅保存在本机，不提交到仓库。

在此目录运行 `pnpm ios`，或双击 `Open-iPhone-App.command`，会依次构建、同步并打开 Xcode 项目。

1. 在 Xcode → Settings → Accounts 登录自己的 Apple 账号。
2. 用数据线连接 iPhone，在手机上选择信任 Mac；按提示开启“设置 → 隐私与安全性 → 开发者模式”。
3. 选择 App target → Signing & Capabilities，勾选 Automatically manage signing，Team 选择自己的 Personal Team。
4. 顶部运行设备选择自己的 iPhone，点击 Run。若系统提示需要信任开发者，在 iPhone 设置中完成信任。
5. 在 App 内登录自己的 English World 账号。

免费 Personal Team 的 provisioning profile 有效期是 7 天。到期后重新连接并 Run；保持 `com.liulin.englishworld` Bundle ID，直接覆盖安装，通常可保留本地数据。不要为了续签先卸载 App。若该 Bundle ID 已被其他开发者占用，首次安装时改为自己唯一的标识，并同步修改 `capacitor.config.ts` 和 Xcode target；之后固定使用它。

Apple 账号、密码和签名文件不应加入仓库。真机系统版本还需要受当前 Xcode 支持。

## 命令

```sh
pnpm build:ios   # 输出 dist-ios；不会覆盖网页 dist
pnpm ios:sync    # 构建并同步安装包资源和原生依赖
pnpm ios:open    # 仅打开已生成的 Xcode 项目
pnpm ios         # 构建、同步、打开
pnpm test:ios    # 使用本机 fixture 做模拟器原生网络测试
```

网页继续使用 `pnpm build`，PWA 注册和缓存仍由网页构建管理；iOS 不注册 Service Worker，不显示 PWA 更新提示。原生通知采用前台 30 秒轮询，无系统推送。原生 HTTP 使用系统 Cookie 存储，原生桥接层在返回 JavaScript 前移除 Set-Cookie 响应头，应用代码不保存登录凭据。

## 原生测试

`pnpm test:ios` 需要已有可用模拟器，也可通过 `IOS_SIMULATOR_ID` 指定。脚本只连接本机 `127.0.0.1:4179`，验证原生 XMLHttpRequest 的登录、HttpOnly Cookie、鉴权、上传 multipart 边界、退出和应用重启后的会话恢复。测试账号是隔离的固定 fixture，不会访问线上用户数据。

脚本临时增加 127.0.0.1 的 HTTP 例外，结束时恢复 Info.plist 和线上构建资源。测试产生的模拟器安装仍是 fixture 版；正式预览/安装前运行 `pnpm ios:sync` 并用 Xcode 再次 Run。签名证书及 Apple 账号不参与模拟器测试。

测试输出放在仓库根目录 `.ios-build/`，不入版本控制。

参考：[Apple 免费账号限制](https://developer.apple.com/support/compare-memberships/)、[Capacitor 环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)。
