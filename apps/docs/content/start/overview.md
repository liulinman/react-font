# 从一个学习动作看懂 English World

## 先确定你想理解什么

English World 把词库、阅读和 AI 学习放进同一套使用流程。技术文档关心的不是把界面按钮逐一复述，而是解释一个动作怎样越过浏览器、HTTP、业务服务和数据库，最后变成可信的结果。例如，让 AI 查一个词，与让 AI 覆盖已经保存的词条，看上去都只有一句自然语言，实际承担的责任不同：查询可以返回当前可见数据，覆盖必须识别账号、检查权限、展示变化，并等待用户确认。

本网站是公开知识入口，不需要平台登录，也不读取读者的词库、笔记或登录令牌。文章里的单词、域名、请求编号都是演示输入；公开文章没有附带可登录的账号。代码位置使用仓库相对路径，帮助有源码权限的维护者定位实现。它们不是浏览器里的下载地址，也不意味着部署服务器与本地目录完全一致。

## 三个边界先记住

前端仓库 `react-font` 使用 pnpm 工作区，学生应用位于 `apps/english-world`，管理应用位于 `apps/admin`。后端是相邻的 `nestjs` 仓库。浏览器访问的 `/api/` 前缀由 Nginx 代理处理，后端控制器通常声明不含这个前缀的路径。数据库保存业务状态，Redis 为 AI 查词提供可降级的缓存，两者不能互相代替。

后端 `src/main.ts` 先加载环境，再验证数据库连接，随后创建 Nest 应用，安装 Cookie、压缩、跨域、异常处理和参数校验。`src/interface/mcp-access/mcp.controller.ts` 则展示了另一条入口：远程 MCP 客户端用 Bearer 授权调用工具。Bearer 是本项目当前采用的接入方式，不能据此推导所有 MCP 服务都必须使用同样的认证形式；本项目目前也没有实现 OAuth 授权流程。

## 用一个输入串起全链路

```text
用户目标：查找词库中包含 example 的词
入口：支持远程 MCP 的客户端
工具：query_words
参数：{ "keyword": "example", "limit": 10, "offset": 0 }
约束：只返回该授权账号可访问的词条
```

这段示例描述工具参数，不是可以直接粘贴给 HTTP 端点的完整协议报文。工具发现、初始化和协议头应交给支持 Streamable HTTP 的客户端。服务端先认证，再根据工具检查范围，最终以账号条件查询数据库；仅仅在页面隐藏其他账号的内容不能形成数据隔离。

## 怎么阅读与验证

建议先读[本地开发](/start/local-development)，理解应用环境与自动化测试环境为什么必须分开，再读[请求生命周期](/backend/nestjs-request)和[数据库隔离](/backend/database-isolation)。想理解修改为什么不会因断网重试执行两次，可以继续读[事务与幂等](/backend/transactions-idempotency)。遇到上线后界面仍旧，则从[旧页面排查](/deploy/stale-page)开始。

验证时始终写清输入、预期和证据范围。静态页面返回成功只能证明资源可访问；匿名接口返回未授权只能证明这一入口拒绝匿名；单个工具通过不能证明全部学习模块通过。文档示例没有在你的环境中自动执行，学习时请在隔离数据上逐步核对，不要把示意输出当成测试报告。
