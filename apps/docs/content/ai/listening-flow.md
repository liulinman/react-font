# AI 完整链路：从词库到生成、听写与反馈

## 要解决什么问题

Freewing（原 English World）的 AI 主线，是把用户已有词库变成可练习、可反馈、可恢复的一轮场景听力。模型负责语言内容，后端负责流程和规则，前端负责交互与播放。理解这条链路，可以回答“用户点击之后发生了什么”，也能定位生成、语音或作答失败的层次。

本文根据当前源码梳理实现；示例是教学构造，未进行真实供应商调用，不代表全量验收或上线结果。仓库 `react-font/` 存放前端，`nestjs/` 存放后端。

## 必要知识：把 AI 放进业务流程

模型返回一段英语，还需要关联用户词条、验证内容、生成声音、保护答案并记录作答，才能成为学习功能。项目用会话 ID 串起这些步骤，用题目 ID 关联音频、播放事件和答案，用词条版本判断练习是否仍适用于当前数据。

```text
选择自己的 1～10 个词
  → 创建会话与词条快照 → DeepSeek 校验 → 看词复习
  → DeepSeek 生成新场景 → 代码检查 → 独立模型语义复核
  → 保存题目 → 返回隐藏答案的公开数据
  → 点击播放 → 豆包合成或读取音频缓存 → 浏览器播放
  → 记录播放事件 → 输入答案 → 服务端判定
  → 展示答案、词形与解析 → 保存记录 → 后续复习
```

一次成功流程通常包含词条校验、场景生成、语义复核三个职责不同的文本模型调用。语音按播放请求获取，缓存命中时不必重新合成；不能把一次练习理解成只有一次外部请求。

## 1. 前端选词，后端确认身份与数据

前端入口为 `react-font/apps/english-world/src/aiListening/AiListeningPage.tsx`，请求封装在同目录 `api.ts`。创建会话时发送 `wordIds` 与 `requestUid`，请求带登录 Cookie；供应商密钥不交给浏览器。

后端入口是 `nestjs/src/interface/ai-services/ai-services.controller.ts` 的 `AiLearningController`，通过 `AuthGuard` 得到当前用户。`ai-services.service.ts` 的 `words` 要求每组 1～10 个词，并按用户 ID 与词条 ID 查询，不能指定另一个账号。服务端保存词条快照和版本，后续准备、播放等操作会检查词条是否变化。

以下是简化请求示意，词条 ID 需要替换为当前账号真实拥有的记录：

```json
{"wordIds":[101],"requestUid":"11111111-1111-4111-8111-111111111111"}
```

`requestUid` 用于识别同一次操作。断网后重复同一意图时复用标识；新意图使用新标识。它不等于对供应商所有付费请求提供全局恰好一次保证。

## 2. 先校验词条，再让用户复习

`create` 先持久化 `review` 会话，再执行 `check`，把拼写、词性、中文目标义和可选例句提交给 DeepSeek。模型给出 `valid`、`suspect` 或 `uncertain`，代码继续确认每个词恰好对应一项结果。校验异常会记录错误与失败状态，用户可以重新校验。

模型不会直接修改原词库。空的可选例句或未分类词性本身不是拒绝理由；确实不确定的词不能进入计分题。前端展示校验结果与词条，用户完成看词复习后再触发 `ready`。

## 3. 生成新场景，再通过两层检查

`ready` 只使用校验为 `valid` 的词，每词生成一道题。它读取当前用户最近其他会话的场景供模型避重，提示模型不要照搬词库例句。答案可以使用原形、真实屈折变化或同词族既有派生词，并附中文词形说明。

第一层由代码检查：数量、关联 ID、题面、答案、词形基本关系、重复全文和提示泄题。若返回双人对话，必须恰好 A/B 两轮，台词拼接后严格等于完整文本。相关逻辑在 `ai-services.service.ts` 的 `ready` 及 `ai-security.ts` 的 `validateQuestion`。

第二层再调用 DeepSeek 进行独立语义复核，对需要验证的词形要求逐项证明。只有通过才进入 `listening`；失败时清空题目并保存错误。这里的“独立”是另一次调用，仍可能存在同一模型的共同错误，内容质量仍需样本评估。

## 4. 保存完整题目，向浏览器返回公开投影

数据库会话保留完整题目；响应经过 `ai-security.ts` 的 `publicSession`，按作答和揭晓情况返回可公开字段。答案、完整文本、解析等反馈信息受服务端控制，不能只用前端隐藏样式保护。

页面默认收起中文场景提示，这是交互选择；服务端不提前返回完整反馈，这是数据边界。二者分别处理。每题从 `ready` 变成 `submitted` 或 `skipped`；所有题都处理后，会话变成 `completed`。

## 5. 用户点播放时获取完整英语音频

`audio` 根据题目获取服务端保存的完整文本，调用 `synthesize`。缓存键包含用户、文本、内容版本、模型、音色等属性，命中则读取已有音频，未命中才合成。双人对话按台词分别处理；第二音色满足配置与测试条件才使用双音色模式。

音频朗读包含答案的完整句子或对话。缺口是视觉题面，不会把音频中的答案消音。浏览器端 `react-font/apps/english-world/src/aiListening/audio.ts` 管理加载、播放、取消和资源回收；切题时旧的迟到响应不应重新响起。前端依据播放事件记录 `played`，音频接口成功不等于设备已实际出声。

## 6. 提交答案，服务端判定并保存反馈

`mutate` 在事务中读取会话、检查操作标识、更新题目并持久化。首次提交要求已有播放记录，答案去掉首尾空格并忽略大小写，与保存的目标答案精确比较。**判分由代码完成，不会每次再请模型评阅。**

首次答对且未揭晓会记录为独立答对；提交后的再次尝试单独记录，不算首次独立作答。播放、慢速、揭晓和失败等事件帮助还原过程。它们来自客户端上报，不能当成防作弊或设备真实出声的强证明。历史由 `history` 读取，供查看记录与后续复习。

## 接口如何串联

下表路径相对业务 API 根路径，默认前缀为 `/api`。JSON 响应由现有接口封装读取 `code/data`，音频响应单独读取二进制。

| 动作 | 方法与路径 | 主要结果 |
|---|---|---|
| 创建与校验 | `POST /ai-learning/sessions` | 会话、词条校验结果 |
| 读取恢复 | `GET /ai-learning/sessions/:id` | 当前公开会话 |
| 重新校验 | `POST /ai-learning/sessions/:id/recheck` | 更新校验结果 |
| 生成场景 | `POST /ai-learning/sessions/:id/ready` | 合格题目或准备错误 |
| 获取音频 | `GET /ai-learning/sessions/:id/questions/:qid/audio` | 音频二进制 |
| 记录交互 | `POST /ai-learning/sessions/:id/questions/:qid/event` | 更新播放等事件 |
| 作答或跳过 | `POST .../questions/:qid/submit`、`POST .../questions/:qid/skip` | 更新题目与反馈 |
| 查看历史 | `GET /ai-learning/history` | 历史会话与复习词条 ID |

## 用一个词走完全程

教学构造：词库有 effective（有效的）。词条校验通过后，生成题面 “We discussed its ______.”，音频是 “We discussed its effectiveness.”。词形记录指出 effective 为形容词，effectiveness 为派生名词。语义复核通过后用户听音频，输入 effectiveness；服务端比较答案，再返回全文与解析。

如果模型用 efficient 代替答案，不能因为意思相近就当成 effective 的派生词。如果词库记录中途改变，服务端会要求重新校验生成，避免用旧题解释新词。这些是源码规则的推演，不是本轮在线执行结果。

## 外部 AI 的另一条链路：通过 MCP 管理词库

平台内听力走上述业务接口。外部客户端则由模型理解意图，通过 MCP 工具查询或维护词库，两条入口共享业务数据，但不必互相调用。

```text
用户向外部 AI 描述意图 → 客户端发现并调用 MCP 工具
  → 独立 Bearer 授权 → 作用域与账号检查
  → 查询 / 新增，或预览更新与删除 → 用户明确确认
  → 业务事务与幂等 → 工具结果 → AI 解释结果
  → 用户回平台选词，开始场景听力
```

入口在 `nestjs/src/interface/mcp-access/`。模型负责建议和工具选择，服务端执行权限、预览和写入规则。连接与安全修改见 [MCP 接入](/mcp/connection) 和 [新增与覆盖](/mcp/write-workflow)。

## 怎样验证和排错

| 现象 | 先核对什么 | 判断依据 |
|---|---|---|
| 无法创建 | 登录、词条归属、数量 | 当前响应与错误信息 |
| 词条不可出题 | 校验状态与目标义 | `validation`、会话 `error` |
| 生成后没有题 | 结构检查、重复场景、语义 gate | 会话错误，不能只看 HTTP 成功 |
| 词条修改后报冲突 | 版本是否变化 | 重新校验再生成 |
| 音频没声音 | 音频响应、解码、实际播放事件 | 浏览器和设备播放证据 |
| 无法首次提交 | 播放事件是否成功记录 | 当前题目的播放记录 |
| 重试后行为不符 | 是否同一意图、同一请求标识 | 会话状态和事件记录 |

真实验证需要自有隔离词条与实际响应：未提交时检查反馈不泄漏；播放确认完整声音；提交后检查判定和持久化；刷新确认会话恢复；越权账号不能读到原会话。构建通过、缓存命中和模拟测试分别证明有限范围，不能代替整条真实链路验收。

## 从短场景到雅思题组

短场景以目标词为中心；雅思形式的听力以整段材料为中心。新的桌面入口为“学习 → 雅思听力”，支持按部分生成原创材料，或准备四部分40个答题位。原创录音的时长和难度不等同正式考试，不换算官方 Band。现有场景听力保持原用途。

准备材料时，主题是选填项，默认留空。指定主题时按该主题组织内容；未指定时由服务端从受约束的场景中选择：Part 1 为日常事务对话，Part 2 为社会生活独白，Part 3 为教育或培训讨论，Part 4 为学术独白。四部分整套分别安排场景；地图题选择适合空间关系和路线表达的场景。自动选题不是让模型自由决定考试结构，题数、题型、限词、答案证据与复核门禁仍然生效。四部分的场景与说话形式依据 [IELTS 官方听力格式](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-listening)。

新增后端入口位于 `src/interface/ielts-listening/`。`material.ts` 校验题号、题干、限词、答案证据和图示结构；`ielts-listening.service.ts` 再调用现有 DeepSeek 做独立一致性复核。AI自称合格不能取代结构检查。雅思生成使用创建时冻结的题组方案、独立JSON写作指令和有界输出额度；该调用按供应商当前接口显式关闭默认思考模式，以免推理消耗输出预算后截断JSON。官方参数说明见 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)；旧短场景调用保持默认配置。地图以同一服务端场景图生成坐标、道路、方位句和答案，再做确定性路线检查；AI负责场所名称及背景语言复核，避免分别生成导致方位矛盾。浏览器渲染几何图形，不执行AI返回的HTML或SVG代码。

当前生成模板让单选题每题使用自己的选项组；多选题默认以一个共同问题对应两个无序答题位，两个题位保留同一完整评分键。导入材料仍按各自指令、题位数量与显式评分键校验。生成器请求一个可由录音逐字支持的填空答案；评分仍按已冻结的显式变体和限词规则执行，不临时扩展同义答案。结构或语义校验拒绝的候选不会进入配音；下一次准备会收到私有的拒绝原因和候选以便修正。每次仍计入现有生成次数限制，达到上限会停止，不因纠错增加配额。显式自我更正按最终确认内容复核，不能仅因录音出现过被否定的旧答案就判歧义。

豆包仍由 `AiServicesService.synthesize` 调用。长台词按不超过1400字符拆成多段，复用已有语音配置、缓存、并发及预算保护。全部部分和音频准备好才允许开始。准备失败保留已完成内容；显式重试携带新的重试标识，并受管理员音频尝试次数限制，未知结果不无限自动重发。`audio-duration.ts` 从实际 MP3 帧读取时长，不能以字符数代替播放时长。

例如一组笔记题要求填写到访日期，题干已有 `on`，答案是 `Monday`。训练模式允许重听和慢速；考试模拟顺序播放，结束后进入120秒检查。文字答案按固定评分键与词数规则判定，大小写及首尾空格不影响结果，近义表达不会临时被AI改判正确。首交前题目响应不含台词、答案和证据，服务端完成评分后才返回结果投影。

`ielts_listening_material` 保存材料，`ielts_listening_attempt` 保存每次作答的材料快照、模式、答案、版本和结果。保存采用版本检查，交卷在事务内固定首次结果；同题再练建立新记录。交卷网络失败时，浏览器会话存储保留冻结答案供本账号恢复重试，不用它替代服务器最终成绩。刷新或中途播放中断的模拟带有中断标记；“一次播放”仅表达播放器记录，不证明考生独立应试能力。

材料列表的关键词同时搜索标题与主题；题型、来源、部分、准备状态和本人完成状态可分别筛选。完成状态由服务端依据本人已交卷历史计算，与材料是否准备好分开，不以其他人的作答推断。

多选题按所需数量显示固定编号答题位，页面显式说明需选数量与不能超选；重复选择保留原答案并提醒，每个正确选项只计一次。配对题说明选项能否重复，不可重复题发现重复答案时提醒考生检查，仍保存原始作答。单选、配对与地图字母题均可用原生下拉框更换或清除；文字地图题保留多词输入。

复盘展示原答案、评分键、原文证据、中文解释与整段回听。每题可由学生自行选择“听不出、词不认识、跟丢、定位错误”，也可清空；这是用户的复盘记录，不由错误答案推断。保存失败显示尚未保存，重选可重试；这些选择不改变首次答案或成绩。缺原文时明确提示暂不可用。没有准确时间标注时不伪造逐题定位。学生可选一个答案词跳到现有词库搜索，主动新增时预填词和听力来源；重复词与覆盖仍沿用既有流程，不自动改词。管理员“雅思听力材料”入口可导入原创材料包、配音、发布和停用；公共可见与个人材料归属分别校验，旧作答使用冻结版本。管理员对已发布材料点击“创建修订”，载入原材料JSON后修改；“校验并创建新版本”保存独立草稿，再按原流程准备和发布，不覆盖原材料或历史卷。取消修订会回到普通导入，不创建版本。

迁移文件为 `migrations/create-ielts-listening.sql`，只新增表。该段描述本地源码行为；供应商替身只能验证流程和持久化，真实出题、声音质量、长音频衔接需要另有实际证据。当前说明不代表已部署。

准备过程中刷新页面后，已创建的材料仍保存在服务端。列表会更新准备状态；当前部分准备完成后，剩余部分可点“继续准备”，全部完成后可开始作答。自己的私有材料与作答记录可分别删除，删除材料保留既有作答记录；公共材料不能由学生删除。材料创建请求在服务端尚未保存前被中断时，不能保证已经创建，请先检查列表再重新生成。

腾讯语音扩展正在验证：雅思对话会保存说话人及与原文逐字一致的台词，再分别以 YunLeo、YunMia 合成；独白使用单一音色。不同供应商的用量分别记录，音频按材料及角色缓存。是否已发布、真实质量与完整整套验证须看交付记录，不能从该设计推断。

### 作答内容与复盘内容的隔离（2026-11-01 修订）

加载另一条作答记录时，仅在记录 ID 与当前路由匹配后展示内容，避免旧结果在新题加载期间闪现。音频连续换段时保持题纸位置及状态区高度，错误才显示恢复提示。交卷后的答题解析、原文和音频回听分别展示；切换区域时暂停回听，防止隐藏区域继续播放。考试模拟的一次播放规则与训练回听行为分别记录。


## 新材料如何避免只换名称（2026-11-04，本地开发未发布） {#listening-diversity}

选“地图专项”时题型保持不变，变化来自空间结构、讲解方式和场景。服务端的 `map-layouts.ts` 定义街区、园区、走廊、展馆四类空间的八种连通结构，分别支持沿连接道路指引、固定地标定位、相对位置描述。`map-plan.ts` 从同一空间事实生成题位、路线和答案，再检查它们是否一致；AI补充与Part相符的地点名及背景，并复核完整台词是否引入矛盾。不能让模型分别猜图、猜路线、猜答案。

“混合题型”也不再只有一套比例。`blueprints.ts` 为每个Part提供至少三种题组方案，总数仍为10个计分位。Part 1保留日常交流，Part 2保留公共介绍，Part 3是学习研究讨论，Part 4是学术独白。组合为本站原创练习设计，雅思官方没有规定本站旧版的固定7+3配比。表格按分类呈现问题、流程按阶段呈现问题，保留原有输入、保存和评分方式。

`ielts-listening.service.ts` 在创建材料时，参考本人各Part最近20份相关材料安排场景与方案，短事务串行保存选择；重复请求返回原材料，失败重试沿用已保存方案。用户主题始终保留；“同题再练”继续练原题。旧ready材料和旧成绩不被新生成规则重写。

新内容通过结构与一致性检查后，`novelty.ts` 比较近期材料的录音正文及问题任务，屏蔽答案词和数字等表面替换，再判断是否需要语义复核。仅共用主题、指令或答案字母顺序不等于重复。确认重复时，在配音前停止并提示重新准备；该次内容尝试仍计入原有限额，不会无限自动重发。比较只使用本人内容，内部方案与历史原文不会下发到作答前客户端。

教学推演：两次生成“预约咨询”，仅把姓名、周五、费用替换成另一姓名、周一、另一金额，任务结构仍相同，应拒绝；同主题改为理解取消条件、区分参与者需求与最终决定，才可能构成不同任务。相似度阈值是有限样本上的工程判断，并非能识别所有语义重复的保证。规则与浏览器自动化可验证结构、保存和拦截行为；真实生成语言、配音质量及接近考试的难度仍需真实材料与试听单独检查。本节描述未提交工作树实现，不表示已发布。

生成提示还要求先确定计分题位、规范答案和连续证据，再安排说话人台词与录音正文。例如答案写作 `90`，原文与证据也要使用相同数字写法；不能用三词课程名填写两词上限，也不能用省略号拼接两处证据。`materialIssues` 会把这类错误和不可重复配对的重复评分键作为下次显式重试的私有诊断。这里是生成约束与失败恢复机制，不代表模型每次都能遵守；被拦截的真实样本不能记作材料通过。
