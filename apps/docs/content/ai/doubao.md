# 豆包语音：从文字到可复用的音频资产

## 问题：重复播放是否要重复生成
听力题会反复播放，同一句话还可能以慢速播放。如果每次都请求语音服务，会增加等待、成本与失败机会。Freewing 将“生成音频”和“播放音频”分开：服务端合成并缓存，浏览器取得音频后负责播放速度。

## 必要知识：内容寻址与幂等
缓存键描述“什么音频”，操作键描述“哪一次生成尝试”。后端仓库 `src/interface/ai-services/ai-services.service.ts` 的 synthesize 对用户、朗读文本、内容版本、模型、资源 ID、音色、格式、采样率和朗读指令求哈希。同一句文本换音色或版本，会成为不同资产；用户维度防止把私有学习音频跨账户复用。

函数先查 ai_audio_cache，命中便记录 cache_hits 并返回。未命中才检查配置、获得并发名额、占用生成操作并扣应用预算，再请求语音服务。操作键包含配置版本和 retryUid，用于区分明确重试。上游超时不一定意味着上游未执行，因此代码还记录 unknown，而不是无条件当作可安全重发。

## 项目请求与返回
项目发送 text、speaker 与 mp3/24000 的音频参数；服务端解析响应后把二进制存入缓存。控制器 `src/interface/ai-services/ai-services.controller.ts` 返回 audio/mpeg，并设置 private, no-store。这里禁止浏览器共享缓存，与数据库内部复用并不冲突。

教学输入是文本 “Please close the window.”、占位音色 `DEMO_SPEAKER` 和内容版本 `demo-v1`；输出是可播放的 MP3 二进制，而非 JSON 中一个可信的外部下载地址。这是数据流示意，没有真实音色有效性或在线合成结果。

## 双声、慢速与验证
只有第二音色配置经过测试且与当前配置一致时，生成流程才选择双声模式；否则走单声。慢速使用前端 playbackRate 0.8，不应据此推断又发生一次语音付费请求。服务端豆包限额独立于 DeepSeek，公共并发仍共同生效。

排查时依次确认缓存是否命中、配置是否就绪、返回类型是否 audio、音频是否可解码和非静音，最后看播放事件。缓存命中说明已有资产可取，不证明当下服务商连通；服务端成功也不证明设备已出声。本篇为源码解读，未触发任何在线合成。
