# DeepSeek：结构化输出仍然需要业务校验

## 问题：合法 JSON 不等于正确题目
模型能返回格式漂亮、含义却错误的练习。例如目标词是 effective，答案却写 efficient；两个词相近，却不属于同一词族。技术上应区分三层：网络成功、结构合法、业务正确。Freewing 的文本生成链路逐层检查，避免把 HTTP 成功当作学习内容合格。

## 必要知识：提示、模式与边界
后端仓库 `src/interface/ai-services/ai-services.service.ts` 的 deepseek 方法向配置的基础地址拼接 `/chat/completions`。system 消息要求把词条当作不可信数据，而非指令；user 消息是序列化后的任务与词条。请求声明 json_object 输出模式，并限制输出长度。随后仍须检查 content 是字符串、JSON 可解析，调用方还要检查字段、数量和语义。

提示防注入与数据验证用途不同。提示要求模型不要服从词条中的指令；代码验证则阻止缺词、重复 ID 或非法词形进入会话。二者叠加也不意味着模型输出获得绝对正确性保证。

## 真实项目中的三次职责
check 负责拼写、词性和中文目标义；ready 生成新句，附词形说明和中文解析；独立 gate 再判断生成内容。空的可选例句与未分类词性不应自动判错，但确实不确定的词不能进入计分题。系统不会让模型直接改写原词库记录。

教学输入可写成：

```json
{"task":"校验词条","words":[{"id":1,"word":"effective","meaning":"有效的"}]}
```

教学输出形状为：

```json
{"words":[{"id":1,"status":"valid","reason":"词义对应","suggestion":""}]}
```

这是简化的构造数据，不是服务商实际返回记录；项目还会核对每个原词恰好对应一项结果。

## 限额与排错
`src/interface/ai-services/ai-limits.ts` 为 DeepSeek 单独保存每分钟、每日、字符、并发与场景尝试限制；公共并发又单独控制全局。它们是本应用策略，不是服务商账户额度或价格说明。请求超时上限、格式损坏、语义不通过也应分别定位。阅读代码和运行本地测试无需付费调用；真正测试服务商连接前要明确授权与预算。本篇仅核对源码，未发送在线请求。
