# React 状态：让页面显示属于当前这轮学习

## 问题：请求结束时，用户可能已经离开
在 A 会话点生成后迅速切到 B，会出现 A 的慢响应覆盖 B 的危险。按钮禁用只能减少重复点击，不能证明异步结果仍属于当前页面。React 的状态管理因此不仅是保存数据，还要管理结果有效期。

## 必要知识：state、ref 与派生值
state 变化触发渲染，适合会话、错误提示和播放指示；ref 保存跨渲染的可变控制信息，适合请求集合和版本号。能够从已有数据计算的内容尽量派生，例如已完成题数由 questions 的 status 计算，避免再维护一份可能不同步的计数。

`apps/english-world/src/aiListening/AiListeningPage.tsx` 用 session 保存服务端会话，用 activeQuestion 和 viewResults 保存当前视图。answers、sceneHints 以题目 ID 为键，不依赖题目在数组中的位置；换题时输入不会错贴到另一题。playback 同时保存 qid、slow 与 loading/playing，避免一个全局布尔值把所有播放按钮都点亮。

## 用代次隔离旧结果
页面用 epoch 表示当前业务代次。safeFetch 发起时记录版本，完成时比较版本并检查取消信号；invalidate 递增 epoch，取消集合内的请求并停止音频。卸载清理也会调用这条路径。取消网络可以节约资源，完成后的版本比较则拦截已经返回但失效的结果，两种手段作用不同。

run 的 lock ref 防止同一时刻重复进入关键操作，busy state 则让界面展示忙碌。runId 用来辨别异步操作归属。不要仅依赖 setBusy 后立即读取 busy：更新需要下一次渲染，连击可能发生在此前。

## 可动手复现的时间线
教学场景：A 请求开始记录 epoch=4；切换会话使 epoch=5；A 随后返回，即使服务器已成功，前端也应抛弃结果。B 的响应属于 epoch=5，才允许更新界面。这是演示时间线，未声称浏览器实测通过。

验证可在测试中控制两个 Promise 的完成顺序，先完成新请求，再完成旧请求，断言仍显示 B。还应覆盖卸载后返回、换题停止音频、提示状态按题隔离。相关回归入口为同目录 `AiListeningPage.test.tsx`；测试存在与测试实际通过需要分别记录。
