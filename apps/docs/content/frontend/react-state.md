# React 状态：让页面显示属于当前这轮学习

## 问题：请求结束时，用户可能已经离开
在 A 会话点生成后迅速切到 B，会出现 A 的慢响应覆盖 B 的危险。按钮禁用只能减少重复点击，不能证明异步结果仍属于当前页面。React 的状态管理因此不仅是保存数据，还要管理结果有效期。

## 必要知识：state、ref 与派生值
state 变化触发渲染，适合会话、错误提示和播放指示；ref 保存跨渲染的可变控制信息，适合请求集合和版本号。能够从已有数据计算的内容尽量派生，例如已完成题数由 questions 的 status 计算，避免再维护一份可能不同步的计数。

`apps/english-world/src/aiListening/AiListeningPage.tsx` 用 session 保存服务端会话，用 activeQuestion 和 viewResults 保存当前视图。answers、sceneHints 以题目 ID 为键，不依赖题目在数组中的位置；换题时输入不会错贴到另一题。playback 同时保存 qid、slow 与 loading/playing，避免一个全局布尔值把所有播放按钮都点亮。

## 用代次隔离旧结果
页面用 epoch 表示当前业务代次。safeFetch 发起时记录版本，完成时比较版本并检查取消信号；invalidate 递增 epoch，取消集合内的请求并停止音频。卸载清理也会调用这条路径。取消网络可以节约资源，完成后的版本比较则拦截已经返回但失效的结果，两种手段作用不同。

run 的 lock ref 防止同一时刻重复进入关键操作，busy state 则让界面展示忙碌。runId 用来辨别异步操作归属。不要仅依赖 setBusy 后立即读取 busy：更新需要下一次渲染，连击可能发生在此前。

## 可动手复现的时间线
教学场景：A 请求开始记录 epoch=4；切换会话使 epoch=5；A 随后返回，即使服务器已成功，前端也应抛弃结果。B 的响应属于 epoch=5，才允许更新界面。这是演示时间线，未声称浏览器实测通过。

验证可在测试中控制两个 Promise 的完成顺序，先完成新请求，再完成旧请求，断言仍显示 B。还应覆盖卸载后返回、换题停止音频、提示状态按题隔离。相关回归入口为同目录 `AiListeningPage.test.tsx`；测试存在与测试实际通过需要分别记录。

## 桌面词典与动态文档阅读（开发中，未发布）

词库的查询、页码和勾选范围仍由 `EnglishWorld.tsx` 管理，`component/WordDictionary.tsx` 只负责“索引选词→完整阅读”。选中项使用词条ID，筛选移走当前词后回到当前页有效词条；编辑继续进入原表单，避免把另一词条的草稿跟着阅读选择一起切换。卡片、学习设置、批量程度、语境题和复习手册继续调用既有业务路径。

知识笔记桌面工作区在列表页使用完整宽度；打开、新建或编辑笔记时默认收起列表，让正文占满阅读工作区。顶部“展开笔记列表”可切回并排浏览，“全宽阅读”再次收起列表。查询条件放在URL中，直接打开笔记链接、返回列表、编辑保存时继续保留范围；列表滚动位置针对实际列表容器保存。文件夹管理和全宽阅读改变呈现，不改变笔记归属和服务端查询。

桌面列表通过 `knowledgeNotes/knowledgeDesktop.css` 单独控制密度：文件夹栏随窗口宽度调整，数量保持单行，长名称省略并可悬停查看完整路径；标题与摘要最多各两行，分类、文件夹和日期使用次级样式。搜索框简写提示，但仍查询标题、正文、例句和来源。勾选笔记后，选中行及批量操作提示使用强调色，复选框继续支持键盘操作。阅读区通过容器宽度判断空间是否足够：窄于650px时把目录移至正文上方，避免只按浏览器宽度判断导致正文被挤窄。这些样式限定在桌面工作区，不改变接口或原文；打开正文仍显示完整标题与内容。

`components/notes/DocumentReading.tsx` 复用现有 VitePress 1.6.4 的官方 `vp-doc.css`，用局部主题变量接入浅深色。正文继续由 `NoteContent` 的 Markdown 语法树安全渲染；目录从已经渲染的真实标题生成，重复标题使用独立ID。这个复用只带入阅读主题，不把个人笔记编译成公开静态页面：内容仍由已有登录接口按账号返回，HTML不执行，Markdown图片仍只显示替代文字。

词条图片选择先展示本地预览，再通过原上传接口取得地址；上传失败保留原图片和表单，上传中禁止提交。只有整个词条保存成功，才更新词条的图片引用。取消不会修改词条；上传文件本身的清理由存储服务既有生命周期负责。

验证应分别检查组件交互、真实接口持久化、Markdown安全和桌面阅读布局。一次截图或单测通过不代表全部PRD已验收；当前实现尚未发布。

## 阅读考试：作答状态与滚动意图

雅思工作区把当前题号与导航动作分开：点击选项只更新答案和当前题号，只有题号导航或切换到作答面板才定位题目。若把自动滚动绑定在当前题号变化上，选项获得焦点也会触发滚动，产生作答时页面跳动。“清除答案”预留固定位置，首次选择和清除时保持题目高度。

题干、填空题空格前后文字及选项使用 `ExamAnnotationText` 划选标注，选中文字后右键选择 Highlight 或 Notes。选项标注使用独立文本块标识，恢复时核对文本和偏移；划词及点击标注不触发选项切换。相关源码位于 `apps/english-world/src/page/englishWorld/contextLab/`，填空题复用 `src/readingPractice/SentenceAnswer.tsx`。例如先选择 FALSE，再划选 TRUE 并高亮，答案仍是 FALSE。这是本次阅读交互更新的实现说明。

考试工作区打开期间还通过带清理函数的键盘事件监听拦截 Ctrl+F / Command+F；准备页、作答及成绩回看一致，卸载后移除监听，普通字母输入不受影响。这只约束页面收到的快捷键，不控制浏览器菜单或已经打开的查找栏。

## 精读词库浮窗

在文章精读正文点击英文单词，可以用一个可拖动的浮窗复习本人词库已保存的释义、音标和笔记；高亮引用仍保留右侧标注编辑。选中短语后，使用选区工具的“查看词库”。本轮后续修订：单词先由现有AI结合原句识别词典原型，再按原型完整拼写匹配本人词库；如sprawls→sprawl。短语仍按完整原文查询。AI不确定、识别/查询失败和确定原型后未收集分别提示，失败可重试。

浮窗的位置与查询结果分开保存：切换词只更新内容，阅读滚动也不改变位置。拖动顶部移动，窗口缩小时将卡片收回可见范围；也可以聚焦标题后用方向键移动、按Escape关闭。正文仍可选中并标注，不能为了单词可点击而改变原文字符和引用偏移。

项目实现位于 `apps/english-world/src/intensiveReading/CollectedWordCard.tsx`，请求effect在换词或卸载时清理旧结果，防止迟到响应覆盖新词。服务端 `english.service.ts` 的 `lookupCollectedWord` 按登录用户和完整词条查询，接口仅返回展示字段，不写词库或阅读笔记。此处说明精读词库卡片的实现；源码片段提交版本仍按各自来源记录。

### 先还原原型再查词

`ReadingWordLookupService`先调用已有AI服务，再调用原`lookupCollectedWord`精确查询。返回原词、原型、识别状态和本人已保存词条，已收集词的释义与笔记来自词库；未收集词的资料由独立的AI释义预览提供。普通派生词不应变成另一个同根词。原句用`<target>`标出点击位置，因此“I saw the saw”中的两个saw可以分别识别。标记只发给服务端，不加入原文DOM，选区偏移继续正确。

前端查询身份包含词和语境，换语境时丢弃旧响应；服务端10分钟、最多256项缓存仅保存当前用户及该语境的原型结果，仍实时读取词库。同key在途去重，复用已有AI密钥、预算和并发控制，不自动调整配额。查询不改词库或精读笔记，AI用量会按现有机制记录。

### 在精读词卡播放发音

匹配到已收集词条后，音标旁的扬声器按钮复用词库现有`BritishPronunciationButton`。例如sprawls匹配sprawl，播放请求传sprawl的本人词条ID；音色和口音继续由管理员的语音配置决定。点击才播放，加载和失败后的显式重试沿用同一组件，未收集词在释义预览成功后，也提供按原型文本播放的入口；不传虚构词条ID。

### 精读笔记原位编辑与不中断的自动保存

编辑动作与表单处于同一条笔记中，才能保持阅读上下文。精读通过稳定的笔记ID保留同一个列表节点，展开后只对右侧笔记栏做必要滚动，收起后恢复该条操作按钮焦点。筛选中正在编辑的笔记先保留，直到主动收起。正文直接显示原文，字号在顶部工具栏调整。

自动保存的网络状态不应成为输入框的禁用状态。`ReadingWorkbench.tsx`将草稿、编辑修订号与提交状态分开：空闲800毫秒后保存；请求中仍能输入，旧响应只有修订号一致才清除待保存标记；后续草稿在前次成功后继续提交。中文组合输入期间暂停提交，避免半成品。失败重试先恢复原请求，再提交新草稿，错误提示留在表单旁。

教学示例：先输入“少数”，请求未完成时继续补“群体”；前次响应不能覆盖“少数群体”，也不能让光标失焦。可在浏览器慢网中观察焦点、选区与最终服务端内容，失败后再输入并重试也需保留后续内容。

### 精读长文输入与等待状态

“请求慢”和“界面处理慢”需要分开测量。笔记每输入一个字，若同时重建数千个正文词节点，即便接口只耗时几十毫秒也会显得卡顿。精读的`AnnotationText`通过memo复用段落渲染，工作台按段分组标注并保持回调身份稳定，让草稿更新只影响表单；服务器确认新标注后仍更新正文。后端在原数组位置替换已有笔记，避免保存使卡片跳到列表末尾。

阅读位置是待提交状态，忙于笔记保存时先保留，空闲后串行提交；重复位置跳过。材料搜索使用250毫秒延迟合并和取消旧请求，分别显示加载、无匹配、空库或可重试错误。创建中的字段固定，避免点击提交后新增输入未被保存。词卡显示可恢复的服务端错误，AI原型识别依然在本人词库查询之前。

验证可用合成长文比较同机原生键盘输入耗时，并记录普通读取与AI冷/热请求总时间。小样本不是P95，合成输入也不是所有用户的实际输入延迟；不能因一次接口正常就排除网络或供应商波动。

### 精读缺词的语境释义与确认收词

缺词并不意味着要离开阅读页。词卡先按既有原型识别查询个人词库；未命中且有原句语境时，自动调用释义预览，AI结合实际点击处解释该词。结果标为参考，显示原型、词性、英式音标、通用中文释义、本句含义、用法和可展开原文语境；可点击播放原型发音，失败可重试。查询和预览不自动收词。

确认动作与预览数据需要由服务端关联。`ReadingWordLookupService`保存短期、用户绑定的已验证预览，确认接口只接收预览标识，复用既有仅补缺词的写入逻辑；已存在词条直接回读，不覆盖笔记或学习资料。新增词保存原型拼写、音标、词性与通用中文释义，并把表层词、语境和用法放进词条笔记，成功后使用现有词条发音按钮。

`AnnotationText.tsx`对高亮内部同样按单词渲染，点击其中一个词查询该词，并保留原标注编辑；整句引用只用于标注与语境，不会作为单词查询。选区工具仍允许显式查短语。

例如正文`sprawls`未收集时，预览原型为`sprawl`，本句含义为“蔓延”；确认后加入`sprawl`，而非另建`sprawls`。另一窗口先收集或响应丢失后重试时，已有记录保留。前端按词与语境隔离异步结果，切词或关闭不会让旧释义盖住当前卡片。

预览保存在当前服务进程中，有效期10分钟；过期或服务重启后需要重新查询。实际AI可能繁忙或不确定，页面显示原因并提供重试，不把异常当成未收集，也不自动调整管理员配置。

正文校对确认成功后的跳转也要等待保存状态提交：`ImportReview` 先清理 dirty，再通过 effect 等待 busy/error 清空后导航，使路由阻拦器先更新，避免保存完成仍停在修订页或弹出多余的离开确认。保存失败则保留编辑与当前页。

### 推理上下文与展示原句分开

查词可以参考邻近句子理解文意，但展示给读者的引用应来自点击词所在的完整句子。`wordLookupContext.ts`保留完整目标句，并在请求长度限制内附带前后文；`<target>`仍标记实际点击位置。后端`reading-word-context.ts`按句子边界提取原句，将它写入预览和新增词条笔记，AI仍收到周围语境。超长句不静默截成半句，沿用接口长度限制报错。

例如“Earlier context. In California, programmes support indigenous languages. Volunteers learn traditional skills.”，点击indigenous时，原文语境只展示“In California, programmes support indigenous languages.”。常见称谓缩写、引号和小数需保留，不能把单纯按句点切割当成完整断句。

已有自动收词笔记的语境块仅在词卡展示时提取单句，不回写或批量改写旧词条；含多处同词、无法确定原句的旧语境明确提示，普通个人笔记保持原样。前端的即时预览也按当前点击位置选句，不将AI返回或历史长段落直接显示为原句。
