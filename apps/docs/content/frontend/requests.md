# 请求封装：把网络、协议与业务失败分开

## 问题：HTTP 200 也可能不能使用
浏览器 fetch 在服务器返回错误状态时通常仍会得到 Response；网络中断才进入异常路径。业务接口还可能在 HTTP 成功里携带失败 code。因此请求封装需要明确判断契约，不能用“没有抛异常”代替成功。

## 必要知识：三种数据通道
Freewing 中 JSON 接口、音频二进制和授权管理具有不同错误策略。`apps/english-world/src/aiListening/api.ts` 的 listeningFetch 无 body 时 GET，有 body 时 POST，并携带登录凭据。它尝试解析 JSON，同时要求 response.ok 与业务 code=200，成功只返回 data。transport 将普通网络异常改为可理解提示，但保留 AbortError，允许调用者把取消当作正常生命周期事件。

同文件 audioFetch 直接读取 Blob，并检查非空和 Content-Type 含 audio/。这是必要的协议校验：错误 HTML 页面即使状态异常配置成 200，也不应该交给播放器当音频。随后 audio.ts 还会解码与检查静音，逐层收紧有效性。

## 为什么授权管理更谨慎
`apps/english-world/src/page/englishWorld/component/McpAccessCard.tsx` 的 mcpAccessFetch 不直接显示服务端错误正文，避免上游消息意外携带凭据。401 显示登录失效，其余显示固定提示。它同时兼容包装的 code/data 和无 code 的直接对象；这属于该接口的项目兼容策略，不能复制后宣称所有 API 都应如此。

## 一个可推演的输入输出
以下为教学响应：

```json
{"code":200,"data":{"id":"demo-session","status":"review"}}
```

listeningFetch 的调用者得到 data 内对象。若 HTTP 200 但 code=500，会进入错误；若收到空音频 Blob，audioFetch 会报“音频无效”；若用户切页取消，请求抛 AbortError，页面可不显示红色失败提示。这些是按源码推演的结果，未发送线上请求。

## 验证与排错方法
测试时分别构造网络拒绝、非 JSON、HTTP 401、业务失败及正常包装，避免只测顺利路径。音频应覆盖错误媒体类型与零字节。排查时先记录状态码和响应类型，再看业务码，不把真实令牌或响应中的私有内容贴入公共日志。已有 `api.test.ts` 可作为回归位置，执行后才可报告通过；本篇仅介绍实现与验证方法。

## 账号表单的异步切换（本地开发版）

`page/login/Login.tsx` 通过 `server/user/user.ts` 描述符使用统一请求封装。每次切换登录、注册或找回都会递增操作版本；旧请求返回时只有版本匹配才更新当前步骤，避免用户已经返回登录却被迟到的邮件响应拉回验证码页。提交锁防止重复点击，服务器仍独立限制发送和验证频率。

注册信息与邮箱验证分两步；返回保留用户名和邮箱，密码与验证码清理，不写localStorage。失败通过可读文案恢复，图形挑战重新获取。注册或重置成功回到登录，不自动建立会话；设置页改密成功后退出学习登录。登录回跳只接受合法站内路径，拒绝外部地址、协议相对地址、反斜线和登录循环。桌面采用确认的左右布局，窄屏复用安全表单，不能通过移动标志绕过图形验证。此段是本地实现说明，真实上线状态以发布记录为准。


## 词库分页缓存

`useWordList.ts` 在当前页面实例内最多保留三页响应，有效期30秒。短时间翻回已访问页可直接复用结果；搜索、重置、刷新和掌握程度更新都会清除缓存，避免修改后继续看到旧记录。缓存不写入浏览器持久存储，首次访问和过期页仍请求服务端。

切换页码时通过 AbortController 取消上一页请求，并保留响应序号校验，防止慢响应覆盖当前页。取消客户端请求不代表服务端数据库查询也已停止。卡片视图等待时显示加载提示，屏幕外卡片使用 content-visibility 减少排版与绘制；这不会减少接口响应体，也不等于已经优化数据库查询。

## 阅读扩展的查询与保存

`apps/browser-reading-extension` 的网页脚本读取用户主动选中的一个词和所在句，扩展后台请求已授权站点的 `/api/browser-reading/explain`。服务端按实际选区解释语境，已收藏词仍可返回这次的中文含义。网页 URL 和标题只在业务层用于绑定来源，AI 接收的是单词及其语境。

点击收藏后，扩展调用 `/api/browser-reading/save`，提交服务端返回的预览标识。词条和首次引用在同一数据库事务中保存；已有词条只追加引用。词库通过 `GET /api/browser-reading/words/:wordId/sources` 读取当前账号的出处。扩展授权依靠一次性授权码和 PKCE，扩展后台持有仅用于查词和收词的凭据，关闭浏览器会清除本地的会话凭据。


### 浏览器阅读扩展 0.2.0 的资料与保存

`/api/browser-reading/explain` 在本人扩展授权下返回 `phonetic`、`meaning`、`sentence`、`sentenceTranslation`、`explanation` 和安全校验后的 `source`。整句译文与词义分开，来自同一次语境生成；只翻译目标句，不把整个段落作为卡片原句。缺失可靠译文时返回错误，不能把词义当成整句译文。

保存请求仍使用短时 `previewToken`，可选 `note` 最多4000字符。旧0.1.0未发送笔记的请求仍兼容。服务在事务内锁定本人词条，确认引用尚未存在，才追加笔记并插入包含 `sentence_translation` 的引用；重试或同一引用并发不能重复追加，旧笔记和学习字段保持。接口本身不信任客户端提供的来源或AI字段。历史引用新增字段为空，显示时不编造译文。

词卡把安全来源标题与完整地址显示出来，可打开原文章。浏览器朗读只在用户点击后使用系统英语语音；音标仍由释义资料提供，语音失败不会阻止查看资料或保存笔记。

### 在词库打开来源链接

桌面词库的「来源链接」可打开最近保存的原网页。`nestjs/src/interface/english/english.service.ts` 在 `/api/english/filterWordList` 中从词条的 `english_browser_citation` 记录读取 `sourceUrl`，已有出处会随列表显示。以 `bank` 为例，先收藏银行新闻，再收藏河岸游记，列表会打开河岸游记，两篇文章仍可在「原文出处」中查看。「引用」继续显示词条原先记录的内容。
