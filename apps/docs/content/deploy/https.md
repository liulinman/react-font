# HTTPS：证书正确之外还要保留哪些配置

## 安全连接是一条链

HTTPS 保护客户端与站点之间的传输，也让浏览器能够使用要求安全上下文的能力。页面没有证书警告，只说明当前连接验证通过；它并不替代平台登录、MCP 授权和账号隔离。English World 当前的远程 MCP 接入用 Bearer，密钥必须经过安全连接传输，并由服务端检查范围、有效期和撤销状态。OAuth 与 Bearer 是认证方案的讨论，不能把项目未实现 OAuth 说成 MCP 协议要求所有客户端手工粘贴密钥。

## 当前项目的部署经验

既有生产部署已经启用 HTTPS，并为续期设置定时检查；同时保留 HTTP 到相同路径 HTTPS 的重定向以及 ACME 验证路径。证书目录和挑战目录通过挂载提供给前端代理。公开教程不展示真实服务器地址、证书私钥或账号；维护者应通过受控运维记录查找实际目标，不能从本文的 example.com 推断线上域名。

生产前端配置比仓库通用 HTTP `nginx.conf` 多出 TLS 与续期相关内容。后续发布如果用通用文件覆盖生产文件，可能让 443 停止监听，或使下次续期验证失败。保留证书挂载和 ACME 目录不是一次性初始化工作，而是每次发布都要检查的不变量。只更新静态资源时，无须为此重新生成证书。

## 用不含秘密的请求核对

```sh
curl -I https://example.com/docs/
curl -I http://example.com/docs/
curl -i https://example.com/api/mcp
```

这些命令是替换域名后可做的只读示例，本页没有执行。第一条应能够通过默认的证书校验；第二条应保留请求路径并重定向到 HTTPS；第三条没有携带授权，应该被拒绝，不能因为文档公开就放开业务接口。不要使用跳过证书校验作为上线成功的证据，那会掩盖名称不匹配、过期和链条不完整等问题。

## 续期失败怎么定位

先区分证书颁发失败与代理加载失败。前者检查挑战路径能否公网访问、定时器是否运行及证书工具日志；后者检查证书挂载位置、文件权限、Nginx 配置校验和加载动作。日志可以保留状态与时间，不能把私钥内容复制出来。短期证书更依赖自动续期，首次成功不能证明长期可靠。

反向代理还需要正确转发 Host、来源协议和客户端地址。前端设置展示的 MCP 公网地址应与站点来源一致，避免把内部 HTTP 地址交给远程客户端。跨域错误与证书错误要分别处理：扩大 CORS 白名单不能修复证书链，重新签发证书也不能使错误来源获得权限。

最终验证应覆盖文档、学生页面、管理页面、匿名保护接口和续期状态，并记录验证时间。涉及静态发布的具体回滚边界见[增量发布与回滚](/deploy/release-rollback)。回滚应用版本时仍应保留现有安全连接，不能把恢复旧界面和取消 HTTPS 绑在一起。
